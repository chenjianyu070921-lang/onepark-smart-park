## 1. 安防告警核心业务流程（主链路，Day 1 重点交付）

覆盖计划要求的全链路：**设备事件接入 → Kafka → 规则匹配 → Redis 去重 → MySQL 入库 → WS 推送 → 确认/解决 → Kafka 通知 M5**。

```mermaid
sequenceDiagram
    autonumber
    participant DEV as 摄像头/门禁/传感器
    participant M1D as M1 event-dispatcher
    participant KFK as Kafka<br/>onepark.device.event
    participant CON as M3 Consumer<br/>(alarm-service)
    participant ENG as 规则引擎<br/>rule/
    participant RDS as Redis<br/>去重
    participant DB as MySQL<br/>alarm_db
    participant ES as Elasticsearch
    participant WSH as WS Hub
    participant WEB as 管理后台/大屏
    participant M5 as M5 dispatch-service

    DEV->>M1D: MQTT 上报设备事件
    M1D->>KFK: 分类路由后生产事件消息
    KFK->>CON: 消费组 alarm-service-group 拉取

    Note over CON: RequestId 幂等校验<br/>(重复消息直接丢弃)

    CON->>CON: 解析 deviceId / eventType / payload
    CON->>ENG: Evaluate(event, 匹配规则)
    ENG-->>CON: 命中 / 未命中

    alt 未命中任何规则
        CON-->>KFK: 提交 offset，流程结束
    else 命中规则
        CON->>RDS: SET alarm:cooldown:{deviceId}:{eventType} NX EX 60
        alt 冷却中（SET 失败）
            RDS-->>CON: 已存在 → 判定重复告警，丢弃
            CON-->>KFK: 提交 offset，流程结束
        else 未冷却（SET 成功）
            RDS-->>CON: OK
            CON->>DB: 创建 Alarm 记录 (status=0 未处理)
            DB-->>CON: alarmId
            CON->>RDS: 更新活跃告警计数缓存
            CON->>ES: 异步双写 alarm_history 索引
            CON->>WSH: 广播新告警
            WSH-->>WEB: WS 推送 (实时上屏)
            CON-->>KFK: 提交 offset
        end
    end

    Note over WEB,M5: ──────── 以下为人工处理闭环 ────────

    WEB->>CON: PUT /api/alarm/:id/ack (确认)
    CON->>DB: status: 0 → 1 (记录 ack_by/ack_at)
    CON->>WSH: 广播状态变更
    WSH-->>WEB: WS 推送更新

    WEB->>CON: PUT /api/alarm/:id/resolve (解决)
    CON->>DB: status: 1 → 2 (记录 resolve_by/resolve_at)
    CON->>KFK: 生产 alarm.event (severity/content)
    KFK->>M5: 消费 → 按 severity 自动创建调度工单
    CON->>WSH: 广播状态变更
    WSH-->>WEB: WS 推送更新
```

**关键技术点对应**：Kafka 消费组 + RequestId 幂等 · 规则引擎 Evaluate（阈值/组合/时间窗口） · Redis `SET NX + TTL` 冷却去重 · GORM 事务写入 · ES 异步双写 · gorilla/websocket 广播 + 心跳 · Kafka 跨模块通知 M5

## 2. 告警状态机

```mermaid
stateDiagram-v2
    [*] --> 未处理: 规则命中且未冷却<br/>创建告警 (status=0)
    未处理 --> 已确认: PUT /:id/ack<br/>记录操作人+时间
    未处理 --> 已解决: PUT /:id/resolve<br/>(是否允许？见 P1-2)

    已解决 --> [*]

    note right of 未处理
        status = 0

    end note
    note right of 已确认
        status = 1

    end note
```

## 3. 门禁远程开门链路（Day 17）

```mermaid
sequenceDiagram
    autonumber
    participant ADM as 管理员
    participant GW as Gateway
    participant M6 as M6 auth-service
    participant AC as M3 access-control
    participant M1 as M1 device-service
    participant EMQX as EMQX
    participant LOCK as 门禁设备

    ADM->>GW: POST /api/access/remote-open
    GW->>M6: gRPC ValidateToken (JWT)
    M6-->>GW: UserInfo
    GW->>M6: gRPC CheckPermission(access:write)
    alt 无权限
        M6-->>GW: 拒绝
        GW-->>ADM: 403 M6-E-0003
    else 有权限
        M6-->>GW: 放行
        GW->>AC: 转发请求 (携带 UserId/RequestId)
        AC->>AC: 校验人员门禁权限 (Redis 缓存)
        AC->>M1: gRPC SendCommand(deviceId, "open_door")
        M1->>EMQX: MQTT Publish
        EMQX->>LOCK: 下发开门命令
        LOCK-->>EMQX: 执行结果
        EMQX-->>M1: 结果回传 (Kafka)
        M1-->>AC: gRPC 响应 (success/message)
        AC->>AC: 记录操作审计 access_operate_log
        AC-->>GW: 返回结果
        GW-->>ADM: 200 {code:"0"}
    end

    Note over AC,M1: gRPC 超时控制 + 失败重试策略<br/>超时/失败同样记审计（result=fail）
```

### 依赖交互明细表

| 序号 | 方向 | 对端服务 | 协议/通道 | 内容 | 契约状态 |
|------|------|---------|----------|------|---------|
| ① | M1 → M3 | event-dispatcher → alarm-service | Kafka `onepark.device.event` | 设备安防事件（门禁异常/人员检测/传感器越限） | ⚠️ **P0-2 消息结构待约定** |
| ② | M3 → M1 | access-control → device-service | gRPC `SendCommand` | 远程开门命令 | ⚠️ **P0-3 proto 待扩展** |
| ③ | M3 → M5 | alarm-service → dispatch-service | Kafka `onepark.alarm.event` | 告警解决事件 → 自动调度工单 | ⚠️ 消费语义待与 M5 对齐 |
| ④ | M5 → M3 | dashboard-service → alarm-service | gRPC `GetActiveAlarms` | 大屏聚合查活跃告警数 | ⚠️ **P0-3 proto 待扩展** |
| ⑤ | 网关 → M3 | api-gateway → 三服务 | HTTP + WS | 路由转发（`/api/alarm/*` `/api/access/*` `/api/video/*` `/ws/alarm`） | ⚠️ **P0-4 网关为空壳，待实现** |
| ⑥ | M3 → M6 | 三服务 → auth-service | gRPC `CheckPermission` | RBAC 权限校验 | ⚠️ 依赖 M6 提供 |
| ⑦ | 网关 → M6 | api-gateway → auth-service | gRPC `ValidateToken` | JWT 校验 + UserId 注入 | ⚠️ 依赖 M6/网关 |

**明确无依赖**：M3 与 M2（物业/访客）无直接调用——访客开门由 M2 自行调 M1；M3 与 M4（能源）无交互。
