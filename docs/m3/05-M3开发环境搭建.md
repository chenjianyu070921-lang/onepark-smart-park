## 4. 必踩坑与待决策项

### 4.1 ⚠️ KI-7（新发现，P0）：Kafka `advertised.listeners` 宿主机不可达

**现象**：compose 中

```yaml
KAFKA_CFG_ADVERTISED_LISTENERS: PLAINTEXT://kafka:9092
ports: - "9092:9092"
```

服务以 `go run` 跑在**宿主机**时，bootstrap `localhost:9092` 能通，但 Kafka 返回的 metadata 中 broker 地址是 `kafka:9092` → 宿主机无法解析 `kafka` 主机名 → **生产/消费全部失败**。
容器内服务（未来容器化）反而正常 → 这是典型的「本机开发能起、一连就挂」。

**修复方案（推荐 B）**：

| 方案 | 做法 | 权衡 |
|---|---|---|
| A | 改 hosts：`127.0.0.1 kafka` | 零改 compose，但每台机器都要改，新人易漏 |
| **B（推荐）** | compose 增加 EXTERNAL listener：`PLAINTEXT://kafka:9092,EXTERNAL://localhost:9094` + 映射 `9094:9094`，宿主机用 9094 | 容器内/宿主机**同时可用**，`.env` 加 `KAFKA_EXTERNAL_PORT=9094`；改动影响全组 compose |
| C | 开发期服务也容器化 | 最一致，但调试不便，Day 3 前成本高 |

> 方案 B 需改 `deploy/docker-compose.yml`（全组共用）→ **需架构/全组确认后执行**。
