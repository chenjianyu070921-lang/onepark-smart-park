# M4 ↔ M1 对接说明（能耗数据）

> 这份文档解决一个问题：**M4 到底怎么收到 M1 的数据**。
> 之前踩过的坑：M1 发到 `device-telemetry`，M4 订阅 `onepark.device.telemetry`，两边各写各的，结果一条都收不到。
> 现在 topic 只有一个来源 —— `common/kafka` 里的公共常量，谁都不许自己起名字。

---

## 1. Topic

| 项 | 值 |
| --- | --- |
| Topic | `device-telemetry` |
| 常量 | `onepark/common/kafka`.`TopicDeviceTelemetry` |
| 生产者 | M1 `device-service`、`event-dispatcher` |
| 消费者 | M4 `energy-data-service`（消费者组 `energy-data-group`） |

**M4 侧不需要在 yaml 里配 topic**：`config.TopicName()` 没读到配置就直接取公共常量。
本地联调要换 topic 时，才在 `etc/energydata-api.yaml` 里把 `Kafka.Topic` 打开覆盖。

## 2. 消息信封（M1 已定，M4 按这个解析）

```json
{
  "request_id": "b3f1...",
  "device_id": "METER-A01",
  "device_type": "meter",
  "event_type": "telemetry",
  "occurred_at": 1757900000,
  "payload": { "energy_kwh": 12345.6, "power_kw": 1.2, "zone_id": "A栋" },
  "source": "mqtt"
}
```

| 字段 | 说明 |
| --- | --- |
| `device_id` | 设备号，对应 `device.device_id`，**必填** |
| `occurred_at` | Unix 时间戳，秒级（毫秒也能识别）；设备没传时 M1 会填上报时刻 |
| `payload` | 设备原始报文，M1 原样透传，**能耗字段在这里面** |

## 3. Payload 里 M4 需要的字段

```json
{ "energy_kwh": 12345.6, "power_kw": 1.2, "zone_id": "A栋" }
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `energy_kwh` | ✅ | 电表**累计读数**（度），不是增量。没有这个字段 M4 会当非能耗事件跳过 |
| `power_kw` | 否 | 瞬时功率，展示用 |
| `zone_id` | 否 | 区域。不传的话 M4 会查 `device.building_id` 补 |
| `reported_at` | 否 | 采集时间字符串（`2006-01-02 15:04:05`）。不传就用信封的 `occurred_at` |

## 4. 区域归属的三级兜底

M1 消息里没有区域，但日报/月报/账单全是按区域聚合的，所以 M4 这样定：

```
payload.zone_id  →  device.building_id  →  默认区域「未分配」
```

最后一档是**兜底不是丢弃**：设备没建档时数据照样入库，只是归到「未分配」。
运维看到日报里「未分配」有量，就知道要去 `device` 表补 `building_id`。

## 5. M4 的清洗规则

| 情况 | 处理 |
| --- | --- |
| payload 里没有 `energy_kwh` | 非能耗事件（地磁/门禁/告警），**静默跳过**，不打错误日志 |
| `device_id` 为空 | 丢弃，记日志 |
| `energy_kwh` < 0 | 丢弃，记日志 |
| 不是合法 JSON | 丢弃，记日志 |
| 时间和电量都正常 | 入库，攒够 50 条或 2 秒批量写，**写完才提交 offset** |

## 6. 自测

```powershell
# 1. 起 Kafka（没有就先建）
docker start onepark-kafka-dev
# 或: docker run -d --name onepark-kafka-dev -p 9092:9092 ... apache/kafka:4.3.1

# 2. 起 M4 服务
cd app/energy-data-service
go run . -f etc/energydata-api.yaml

# 3. 按 M1 格式发一批消息（8 正常 + 1 无区域 + 2 非能耗 + 3 脏数据）
go run ./cmd/mockproducer

# 4. 看日志: 应该"已入库 9 条", 非能耗事件没有报错, 脏数据 3 条有告警
# 5. 验证查得到
curl "http://localhost:8061/api/energy/realtime/MOCK-01"
```
