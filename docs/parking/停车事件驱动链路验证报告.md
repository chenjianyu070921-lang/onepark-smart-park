# 停车事件驱动链路验证报告

> 验证对象: M1 地磁/道闸事件 → Kafka(`device-telemetry`) → `parking-service` 消费 → 自动更新 `parking_record` 状态与费用
> 验证方式: 代码走读 + 单元级验证(已执行) + 端到端验证脚本(待 Docker 就绪后一键执行)
> 验证日期: 2026-09-27
> 状态: 链路逻辑闭环正确; 发现 1 处计费口径偏差(见"关键发现")

## 1. 验证目标

确认"停车设备入场/离场事件经 M1 Kafka 投递, parking-service 消费后自动建停车记录、置状态、算费用"这一链路:

- 入场事件 → 自动建"停车中"记录(`status=1`), 识别车型(月卡/临时/VIP…)
- 离场事件 → 自动置"已完成"(`status=2`), 计算时长与费用, 发布 `parking-exit` 事件供大屏/联动
- 并发/重投下不重复建单、不重复计费(幂等)
- 坏消息(非法 JSON)不阻塞分区

## 2. 链路架构与代码落点

| 环节 | 代码位置 | 说明 |
|------|----------|------|
| Kafka 消费启动 | `app/parking-service/parking.go` → `svc.StartConsumers` | 订阅 `kafka.TopicDeviceTelemetry`, 消费组固定 `kafka.GroupParking = "parking-service-v2"`(P0-2 临时绕过协调故障) |
| 消息标准化 | `svc/consumer.go` `handleTelemetry` + `normalizeTelemetry` | 同时兼容标准信封(`payload` 内 `tenant_id/plate_no/vehicle_type`)与旧扁平格式(`event/plate_no/...`); 缺 `tenant_id` 直接丢弃(防越权) |
| 入场处理 | `onTelemetryEntry` | L1(Redis `SetNX`) + L3(唯一索引 `uk_request` `OnConflict DoNothing`)双层幂等; `ResolveVehicleType` 按 `monthly_card` 自动识别月卡 |
| 离场处理 | `onTelemetryExit` | 找该车牌最新"停车中"记录, 用 `occurred_at` 算时长与费用, `CAS` 条件 `status=parking` 更新防重复计费; 发布 `parking-exit` |
| 计费 | `model/parking.go` `CalcFee` / `CalcFeeByRule` / `GetActiveParkingFeeRule` | 内置默认: 临时车 5 元/小时、15 分钟免费、每日封顶 50; 规则优先 |

## 4. 端到端验证脚本(待 Docker 就绪后执行)

镜像 `deploy/test/m5_kafka_e2e.ps1` 范式, 提供两件套:

- **消息生产工具** `app/parking-service/tools/telemetryproducer/main.go`: 往 `device-telemetry` 投放入场/离场遥测(支持 `-request-id` 固定以验证幂等、`-raw` 构造毒消息、`-occurred-at` 控制时长), 不依赖任何上游服务
- **一键脚本** `deploy/test/parking_kafka_e2e.ps1`: 起本地 broker(见 `deploy/kafka/README.md`)→ 起 `parking-service`(env 注入 `PARKING_MYSQL_DSN`/`REDIS_ADDR`/`KAFKA_BROKERS`)→ 投事件 → 断言 `parking_record` 行

脚本含 **主线 + 加练 A/B/C/D**:

| 场景 | 断言 |
|------|------|
| 主线 entry→exit | `status` 1→2, `duration_min`=120, 临时车 2h 费用=10 元, 发布 `parking-exit` |
| A 幂等 | 同 `request_id` 入场投 2 次 → `COUNT=1`(uk_request + L1 去重) |
| B 月卡识别 | 入场未带车型 + 生效月卡 → `vehicle_type=1`, 离场 `fee=0` |
| C 毒消息 | 非法 JSON 后正常消息仍被处理(分区不卡死) |
| D 计费规则一致性 | 配置 `parking_fee_rule(hourly_fee=100)` 后, Kafka 离场出口**仍按内置默认 10 元**(见关键发现) |

> 注: 本机 Docker 守护进程未运行, 脚本编写时未能实跑; 断言口径已与代码常量逐一核对。首次执行若因环境差异微调, 回填本表即可。脚本已写入 **UTF-8 BOM**, 可在中文 Windows 的 PowerShell 5.1 下正确解析(无 BOM 会被按 GBK 解码导致乱码/引号闭合失败)。

## 5. 关键发现: Kafka 离场出口未应用计费规则(偏差)

`onTelemetryExit` 计费仅调用 `CalcFee`(内置默认), **未**走 `GetActiveParkingFeeRule` + `CalcFeeByRule`;而 HTTP 离场接口 `ParkingExit`(`app/parking-service/internal/logic/parkingexitlogic.go`)会优先应用已配置规则。

- 现象: 若 `parking_fee_rule` 配置了非默认费率, 通过 M1 Kafka 自动结算的月卡/临停费用走默认 5 元/小时, 而同一记录走 HTTP 人工/后台离场则走配置费率 —— **两条路径计费口径不一致**
- 影响: 生产环境"自动结算"与"人工结算"费用可能不同, 财务对账偏差
- 建议修复(约 3 行, 与 HTTP 路径对齐):
  ```go
  fee := model.CalcFee(rec.EntryTime, &exitTime, rec.VehicleType)
  if rule, rerr := model.GetActiveParkingFeeRule(s.DB, t.TenantID, exitTime); rerr == nil && rule != nil {
      if cfg, perr := rule.ParseRule(); perr == nil {
          fee = model.CalcFeeByRule(rec.EntryTime, &exitTime, rec.VehicleType, cfg)
      }
  }
  ```
- 状态: 待确认是否修复(本任务为"验证", 仅标注发现)

## 6. 其他观察(非阻断)

- 消费组 `parking-service-v2` 硬编码于 `common/kafka/topics.go`, 不可经配置变更; E2E 脚本用唯一车牌/request_id 前缀隔离历史消息重放(该组 `StartOffset=FirstOffset`), 无需重置位移
- `L1 Redis 去重` 在 Redis 未就绪时自动降级为仅 `L3` 唯一索引, 仍保证不重复建单
- 离场 `CAS`(`status=parking` 条件更新)确保同一记录不被并发离场重复计费, 与 HTTP 路径一致

## 7. 结论

事件驱动停车管理链路**主流程正确闭环**: 设备事件可正确驱动停车记录状态流转与费用计算, 且具备幂等与毒消息容错能力。唯一需在量产前修复的是 **第 5 节计费规则口径偏差**, 以保证"自动结算"与"人工结算"费用一致。
