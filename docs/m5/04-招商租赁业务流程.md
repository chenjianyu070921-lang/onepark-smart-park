# M5 招商租赁业务流程（leasing-service）

> 对应组长一周计划书：**周一 P0** 合同创建/详情/列表、**周二 P1** 合同状态机、**周三 P0** 入驻率、
> **周三 P1** 自动账单 / 到期提醒、**周四 P0** 合同到期自动处理。

## 1. 合同生命周期

```
待生效(1) ──activate──► 生效中(2) ──expire──► 已到期(3)
                 │         │  ▲
                 │         │  └──renew(续签: 顺延租期, 状态仍生效中)
                 │         │
                 └─────────┴──terminate──► 已终止(4)
```

| 动作 | 说明 |
|---|---|
| `activate` | 待生效 → 生效中。**只有「生效中」的合同计入入驻率与出账** |
| `renew` | 顺延终止日、可调整租金；租期长度按**原租期长度**顺延（不是写死一年） |
| `expire` | 生效中 → 已到期。正常由定时任务每日自动执行，接口入口用于**补偿处理与联调** |
| `terminate` | 终止（含原因） |
| `update` | 变更续约条款（`auto_renew` / `renew_notice_days`，`-1` 表示不动） |

**为什么必须真有 `expire` 动作**：若「生效中 → 已到期」没有实现，到期合同会永远挂在「生效中」，继续被计入入驻率、继续出账单 —— 入驻率与账单口径同时失真。这是数据正确性问题。

## 2. 每日定时任务（00:05，顺序不可颠倒）

```
① 自动续约  autoRenew(): auto_renew=1 且已过终止日 → 按原租期长度顺延, 状态保持「生效中」
② 自动到期  expireDue(): 其余已过终止日且仍「生效中」 → 转「已到期」
```

**顺序为什么不能颠倒**：先跑到期会把「约定自动续约」的合同也转成已到期，再续约就得跨状态处理，徒增复杂度。

**启动补偿**：服务可能停机跨过 00:05（周末关机、发版宕机），启动时先补执行一次，避免到期合同一直挂着污染口径。

### 三层防重复（锁会丢，不能只靠锁）

1. Redis `SET NX` 锁（按日期，10 分钟 TTL）+ **Lua 比对持有者释放**（直接 `DEL` 会删掉别人刚抢到的锁）
2. 更新条件带 `status AND version` —— **数据库层兜底**，锁失效也不会重复转移
3. 审计流水仅在 `RowsAffected > 0` 时写 —— 一份合同只留一条 expire 流水

## 3. 月度租金账单（每月 1 号 00:10）

**与每日任务错开 5 分钟**：出账依赖「该到期的合同已经转过状态」这一结果；同一时刻启动会让两者争抢连接与锁，日志也难以归因。

**幂等两层**：

| 层 | 作用 |
|---|---|
| `uk_contract_period(contract_id, billing_period)` 唯一索引 | **幂等的根基**，即使锁失效也不会重复出账 |
| Redis 分布式锁 | 只用于避免多实例同时跑做无用功，**不承担幂等职责**（锁会丢） |

账单金额直接取合同的 `monthly_rent` **decimal 原值，不做任何浮点运算**。

**复用**：定时任务与手工接口 `POST /api/lease/bill/auto` 共用同一个 `BillAutoLogic` —— 账单生成涉及「锁 + 唯一索引幂等 + 单条失败不中断整批」三件事，复制一份就等于给同一业务留了两个真相来源。

## 4. 入驻率统计

```
入驻率 = SUM(生效中合同的 area_sqm) / SUM(lease_zone.total_area_sqm)
```

| 细节 | 处理 |
|---|---|
| 分子只算「生效中」 | 待生效/已到期/已终止都不占面积 |
| 可租总面积为 0 | 返回 `0` 而非 `NaN`（前端显示会炸） |
| 聚合用 `COALESCE(SUM(...), 0)` | `SUM` 无匹配行返回 NULL，Scan 进 Go 非指针基础类型会报错 |

## 5. 金额精度约定

**全链路禁止 float64 承载金额**：

| 环节 | 做法 |
|---|---|
| DDL | `DECIMAL(12,2)` |
| Go | `shopspring/decimal` |
| HTTP / gRPC 输出 | **字符串**（如 `"10000.50"`），不用 JSON 数字 |
| 渲染 | `moneyString()` = `StringFixed(2)`，**按列声明的精度补零** |

> 最后一条是 2026-09-17 补的：`decimal.String()` 会丢掉末尾的零 —— DB 里存的是 `10000.50`，读回来渲染成 `"10000.5"`，前端就显示「月租 ¥10000.5」。数值虽相同，但金额的规范表示应与列声明的精度一致。

## 6. 到期提醒

`GET /api/lease/contracts/expiring?days=30`

| 细节 | 处理 |
|---|---|
| 范围 | `end_date <= today + N`，**含已逾期未处理的合同**（`days_left` 为负） | 
| 排序 | 按 `end_date` 升序 —— 最先到期（或已逾期）的排最前 |
| 默认窗口 | 30 天（可自定义） |

> 为什么用 `<=` 而不是 `BETWEEN today AND today+N`：漏掉已逾期未处理的合同，恰恰是最需要催的那批。
