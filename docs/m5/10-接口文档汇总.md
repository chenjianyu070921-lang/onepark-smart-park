## 一、总览

| 协议 | 服务 | 监听 | 前缀 / 路径 | 数量 |
|---|---|---|---|---|
| HTTP | `leasing-service` | `:8051` | `/api/lease/**` | 13 |
| HTTP | `dashboard-service` | `:8052` | `/api/dashboard/**` | 3 |
| HTTP | `dispatch-service` | `:8053` | `/api/**` | 8 |
| gRPC | `leasing-service` | `:9051` | `onepark.leasing.LeasingService` | 3 |
| WS | `dashboard-service` | `:8052` | `/ws/dashboard?token=` | 1 |

**合计：24 个 HTTP + 3 个 gRPC + 1 个 WS。**

> ⚠️ 健康检查 `GET /health` 三个服务各有一条，**无 `/api` 前缀**（不在网关映射范围内），探活要直连服务端口。

### 鉴权与租户口径（所有接口通用）

| 入口 | 身份从哪来 |
|---|---|
| 走网关 | 网关注入 `x-user-id` / `x-role-ids` / **`x-tenant-id`**，业务服务只透传 |
| 直连服务 | 自己带 `x-tenant-id`（不传按 0 查，**可能什么都查不到**） |
| gRPC | 不经过网关，由 `rpcserver` 把调用方声明的 `req.tenant_id` **注入 ctx** |
| WebSocket | 浏览器无法自定义头 → 走 `?token=`（必须是 access 类型） |

> **租户只从 ctx / 网关注入取，绝不从请求体或查询参数取** —— 2026-09-21 修掉的「账单三接口租户越权」就是这个坑，
> 2026-09-27 又把入驻率里那个**看着能用其实不生效**的 `tenant_id` 参数删掉了（留着会诱导后人改成读它）。
> 跨租户查看属 RBAC 数据范围，由网关 `x-data-scope` 收口。

## 二、leasing-service（13 + gRPC 3）

| # | 方法 | 路径 | 用途 | 关键参数 |
|---|---|---|---|---|
| 1 | POST | `/api/lease/contract` | 新建合同 | `tenant_name`/`zone_code`/`area_sqm`/`monthly_rent`/`start_date`/`end_date`/`auto_renew`/`renew_notice_days` |
| 2 | GET | `/api/lease/contracts` | 合同分页列表 | `status`(0=不限)、`tenant_id`、`page`、`page_size` |
| 3 | GET | `/api/lease/contract/:id` | 合同详情 | path `id` |
| 4 | PUT | `/api/lease/contract/:id` | 合同变更/流转 | `action`：`activate`/`renew`/`terminate`/`expire`/`update` |
| 5 | GET | `/api/lease/contracts/expiring` | 即将到期（到期提醒） | `days`、分页 |
| 6 | GET | `/api/lease/bills` | 账单分页列表 | `billing_period`、`status`、`contract_id`、`tenant_id` |
| 7 | GET | `/api/lease/bills/summary` | 账单汇总（应收/已收/欠费） | `period`（空=全部账期） |
| 8 | POST | `/api/lease/bill/auto` | 生成月度账单（**幂等**） | `period`（空=上一自然月） |
| 9 | PUT | `/api/lease/bill/:id/status` | 缴费状态流转 | `action`：`pay`/`unpay` |
| 10 | GET | `/api/lease/zones` | 可租区域列表 | 分页 |
| 11 | POST | `/api/lease/zone` | 区域 upsert（`zone_code` 为业务唯一键） | `zone_code`/`zone_name`/`total_area_sqm` |
| 12 | GET | `/api/lease/occupancy` | 入驻率（已租/可租） | **无 tenant 参数**（见上文口径） |
| 13 | GET | `/health` | 健康检查 | — |

**gRPC `LeasingService`**（`proto/leasing/leasing.proto`）

| 方法 | 说明 | 租户口径 |
|---|---|---|
| `Ping` | 探活 | — |
| `GetContract` | 按主键查合同 | `req.tenant_id` 注入 ctx；**0 = fail-closed**（不是"看全部"）；租户不匹配返回 `NotFound`（避免泄露"该合同存在"） |
| `GetOccupancy` | 园区入驻率 | 同上（2026-09-27 修：原先没注入 ctx，导致**非 0 租户查出来恒为 0**） |

## 三、dashboard-service（3 + WS）

| # | 方法 | 路径 | 用途 |
|---|---|---|---|
| 1 | GET | `/api/dashboard/overview` | **大屏主接口**：四路聚合（工单/告警/设备/能耗） |
| 2 | GET | `/api/dashboard/home` | 首页轻量卡片（只有工单一路） |
| 3 | GET | `/health` | 健康检查（DB + Redis） |

### 响应语义（前端必读，详见 09 的第五节）

| 字段 | 语义 |
|---|---|
| 某卡片为 `null` | 该路**数据不可用**（≠ 0）→ 渲染「暂不可用」 |
| `degraded` | 不可用的数据源名列表（`work_order`/`alarm`/`device`/`energy`） |
| `cached` | 本次是否命中 30s 缓存 |
| `updated_at` / `elapsed_ms` | 聚合时间（**秒**）/ 聚合耗时（毫秒） |
| `avg_handle_sec`、`total_water` | **可空**：上游契约没提供时为 `null`，代码里明确「不用 0 冒充」 |

> **为什么卡片会 null 而接口仍 200**：`NonBlock` + singleflight + 逐源超时的设计目标就是
> 「**任何一路挂掉都不影响另外三路**」，上游全挂时大屏仍能渲染出"哪几路不可用"。

### WebSocket `/ws/dashboard?token=...`

两条通道合一：`snapshot`（每 5s 一帧全量）+ `event`（Kafka 事件到达即推增量）。
字段与前端分发建议见 `09-前端对接说明.md` 第六节。

## 四、dispatch-service（8）

| # | 方法 | 路径 | 用途 | 关键参数 |
|---|---|---|---|---|
| 1 | POST | `/api/dispatch` | 建工单 | `title`/`source`(1 人工)/`zone_code`/`required_skill`/`priority`/`description` |
| 2 | GET | `/api/dispatches` | 工单分页列表 | `status`/`priority`/**`zone_code`**/分页 |
| 3 | GET | `/api/dispatch/:id` | 工单详情 | 响应 `{task, logs}`，**`logs` 是状态流转时间线** |
| 4 | PUT | `/api/dispatch/:id/assign` | 指派/改派 | `assignee_id`（0 = 走自动指派） |
| 5 | PUT | `/api/dispatch/:id/status` | 状态回写 | `action`：`start`/`finish`/`close` |
| 6 | POST | `/api/dispatch/staff` | 人员 upsert | `staff_id`/`name`/`zone_code`/`skills`/`on_duty` |
| 7 | GET | `/api/dispatch/staffs` | 人员列表 | `on_duty`(-1 不限)/分页 |
| 8 | GET | `/health` | 健康检查 | — |

> ⚠️ **路径拼法**：前缀 `/api` + 路由自带 `dispatch` → 建单是 `/api/dispatch`、列表是 `/api/dispatches`
> （**不是** `/api/dispatch/dispatch`）。以本表为准。

### 时间线（`logs`）字段

| 字段 | 说明 |
|---|---|
| `from_status` | 流转前状态；**`0` = 不存在**（建单那一刻，时间线第一帧） |
| `to_status` | 1 待指派 / 2 已指派 / 3 处理中 / 4 已完成 / 5 已关闭 |
| `action` | `create`/`assign`/`release`/`start`/`finish`/`close` |
| `operator_id` | **`0` = 系统**（cron 超时重派 / 告警自动建单），不是"没人操作" |
| `created_at` | **秒**级时间戳 |

> 时间线按 `id` 升序返回，**允许有缺口、不允许乱序**。

## 五、错误码

### M5 自有码（`internal/ecode`，格式 `M5-{E|W}-{模块段}{序号}`）

| 码 | 含义 | 出处 |
|---|---|---|
| `M5-E-1001` | 合同不存在 | leasing |
| `M5-E-1002` | 合同状态不允许该操作 | leasing |
| `M5-E-1003` | 合同创建失败 | leasing |
| `M5-E-1004` | 合同更新失败 | leasing |
| `M5-E-1005` | 账单生成失败 | leasing |
| `M5-E-1006` | 区域编码非法 | leasing |
| `M5-E-1007` | 合同冲突（唯一键/乐观锁） | leasing |
| `M5-E-1901` ~ `1904` | 合同列表 / 合同查询 / 入驻率统计 / 到期查询 失败 | leasing |
| `M5-W-1001` | 租赁参数非法（W = warning 级） | leasing |
| `M5-E-2001` | 工单不存在 | dispatch |
| `M5-E-2002` | 工单创建失败 | dispatch |
| `M5-E-2003` | 工单更新失败 | dispatch |
| `M5-E-2004` | 状态流转非法 | dispatch |
| `M5-E-2005` | 人员负载查询失败 | dispatch |
| `M5-E-2006` | 指派失败 | dispatch |
| `M5-E-2007` | 无人可派 | dispatch |
| `M5-E-2008` | 工单冲突（唯一键/乐观锁） | dispatch |
| `M5-E-2901` / `2902` | 工单列表 / 工单查询 失败 | dispatch |
| `M5-W-2001` | 调度参数非法 | dispatch |

### 通用码（`common/errorx`，各模块共用）

`M6-E-0001` 参数错误 ｜ `0002` 未登录 ｜ `0003` 无权限 ｜ `0004` 资源不存在 ｜ `0005` 服务器内部错误 ｜ `0006` 依赖中间件连接失败。

### 响应体形状

```json
{ "code": "M5-E-2004", "msg": "状态流转非法" }
```

> ⚠️ **`code` 是字符串**（不是 go-zero 默认的整数）→ 前端比较错误码要用字符串相等，别 `parseInt`。
>
> ⚠️ `05-接口与数据契约.md` 里那张码表**已过时且与实现语义冲突**（它还写着"M5-E-1003 合同编号重复"等）。
> **以本文与 `internal/ecode/ecode.go` 为准**，05 待修。
