## 2. WebSocket 消息协议

```jsonc
// ① 周期快照（每 5s）
{
  "type": "snapshot",
  "data": {
    "device":    { "total": 0, "online": 0, "offline": 0, "fault": 0 },
    "work_order":{ "today_total": 0, "unfinished": 0, "avg_handle_sec": null, "complete_rate": 0 },
    "alarm":     { "total": 0, "critical": 0, "major": 0, "minor": 0, "info": 0 },
    "energy":    { "total_kwh": 0, "total_water": null },
    "degraded":  ["energy"],      // 失败的数据源
    "cached":    false,
    "elapsed_ms": 3,
    "updated_at": 1758000000
  }
}

// ② 事件增量（Kafka 事件到达即推）
{
  "type": "event",
  "source": "alarm",              // alarm | workorder
  "topic": "alarm-event",
  "received_at": 1758000000,
  "data": { /* Kafka 原始消息体, 原样透传不解析 */ }
}
```

**降级约定**：某路失败 → 该字段 **`null`** 且列入 `degraded`，消息与接口本身**不报错**。字段为 `null` 表示「当前不可用」，**不是**「值为 0」。
- `energy.total_water` 恒为 `null`：M4 契约当前只提供电耗，**不用 0 冒充「没用水」**。
- `work_order.avg_handle_sec` 在无已完结工单时为 `null`。

## 3. gRPC 契约

`proto/leasing/leasing.proto` · `leasing-service` · **9051**

| 方法 | 请求 | 响应 |
|---|---|---|
| `Ping` | `Empty` | `Empty`（不依赖 DB） |
| `GetContract` | `{id, tenant_id}` | `{Contract}`；`tenant_id≠0` 时校验归属，跨租户返回 `NotFound` |
| `GetOccupancy` | `{tenant_id}` | `{total_area_sqm, leased_area_sqm, occupancy_rate}` |

**`Contract` 字段口径**（与 HTTP 完全一致，同一 logic 实现）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `monthly_rent` / `deposit` | **string** | decimal 原值，如 `"10000.50"`。**protobuf 无 decimal，用 double 会重现金额精度问题** |
| `area_sqm` | double | 沿用 HTTP 契约（非金额字段） |
| `start_date` / `end_date` | string | `yyyy-MM-dd`，避免各语言时区解释不一致 |
| `status` | int32 | 1 待生效 / 2 生效中 / 3 已到期 / 4 已终止 |
| `auto_renew` | bool | 由 DB 的 `int8(0/1)` 换算 |

**M5 不消费他人 gRPC，只作为 Client**：`GetDeviceStat`(M1 9001) / `ListWorkOrders`(M2 9091) / `GetActiveAlarms`(M3 9009) / `GetDailyReport`(M4 9061)。

## 4. 数据表

### 4.1 `leasing_db`

| 表 | 关键约束 |
|---|---|
| `lease_contract` | `uk_contract_no`；`idx_status_end_date`；`version` 乐观锁；`auto_renew` / `renew_notice_days` |
| `lease_zone` | `uk_zone_code`；`total_area_sqm` 是入驻率分母 |
| `lease_bill` | **`uk_contract_period(contract_id, billing_period)` —— 出账幂等的根基** |
| `lease_contract_status_log` | 状态流转审计（"能不能改"归 FSM，"改过之后能查"归本表） |

### 4.2 `dispatch_db`

| 表 | 关键约束 |
|---|---|
| `dispatch_task` | `uk_task_no`；**`uk_alarm_id`（自动建单幂等键，必须 NULL 可空）**；`assign_expire_at` + `reassign_count` |
| `dispatch_task_log` | 状态流转审计；`action = create/assign/release/start/finish/close`；`operator_id=0` 表示系统操作 |
| `dispatch_staff` | `uk_staff_id`；`skills` 逗号分隔（几十人量级，拆表不划算）；`on_duty` 是派单硬过滤 |

> ⚠️ `dispatch_task.alarm_id` **必须 NULL 可空**：MySQL 唯一索引允许多个 NULL，若用 `''` 默认值，**第二张人工单就会撞唯一键**。

### 4.3 `dashboard_db`

**没有业务表** —— dashboard-service 是纯聚合方，不持久化业务数据；它只连 Redis 做聚合缓存。

## 5. 错误码

M5 目前统一使用 `common/errorx` 的**通用码**：

| 码 | 含义 | M5 使用场景 |
|---|---|---|
| `M6-E-0001` | 请求参数错误 | 入参非法、**状态机拒绝的非法转移**（返回 HTTP 400） |
| `M6-E-0004` | 资源不存在 | 合同/工单不存在；**gRPC 跨租户查询也返回它**（不泄露"该资源存在"） |
| `M6-E-0005` | 服务器内部错误 | 查询/写入失败 |
| `M6-E-0006` | 依赖中间件连接失败 | DB/Redis 未初始化 |

## 6. 库表约定（M5 遵循）

| 约定 | 原因 |
|---|---|
| 每服务独立库，**禁止跨库 JOIN** | 服务边界；跨库 JOIN 会把两个服务耦合成一个 |
| 金额 `DECIMAL(12,2)` + Go `decimal`，**禁止 FLOAT/DOUBLE** | 浮点累加产生精度误差 |
| `version` 乐观锁 | 并发修改用 `WHERE id=? AND version=?` 兜底，不依赖锁 |
| `created_at` / `updated_at` 用 DB 默认值 | 避免应用时钟不一致 |
| 状态字段用 `TINYINT` + Go 常量 | 可读性在代码层，不靠 DB 注释 |
