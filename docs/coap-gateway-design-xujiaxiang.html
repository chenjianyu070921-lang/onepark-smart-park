三、设计缺口补充：CoAP 无状态认证策略

⚠ 问题

当前 TCP 流程：建连 → auth 一次 → 后续帧携带 authed=true 状态。但 CoAP 是 UDP 无状态协议，每个请求独立，没有"连接"概念。原方案未明确 CoAP 模式下 Session 的 authed 状态如何管理。

三个候选方案对比

方案做法优点缺点推荐
A 每请求全量认证 每个 CoAP 请求都带 device_id + secret，每次查库 + bcrypt 最简单，无需 token 管理 每次请求都查库 + bcrypt，性能差 不推荐
B 临时 token auth 一次后返回临时 token，后续请求带 CoAP Token Option 性能好 需新增 token 管理（生成/过期/吊销） 备选
C DTLS 身份即认证 DTLS 握手阶段 PSK 已确认设备身份，应用层不重复 bcrypt；NoSec 模式下每请求带 device_id+secret 最简洁，无额外状态，双因子不重复 NoSec dev 模式仍需每请求认证 推荐

推荐策略（方案 C）

// CoAP 认证策略
if DTLSEnabled {
    // DTLS 握手时 PSK 标识 = device_id，PSK 密钥 = device_secret
    // 握手成功即确认设备身份，应用层直接信任，不再重复 bcrypt
    // Session 从 DTLS ConnectionState 提取 device_id，置 authed=true
    deviceID = extractDeviceIDFromDTLS(pskIdentity)
    authed = true
} else {
    // NoSec 模式（dev/test）：每个请求必须带 auth 帧
    // Session 无状态，每请求独立认证
    if f.Type != TypeAuth { return ErrUnauthenticated }
    authed = bcryptVerify(deviceID, secret)
}

四、核心架构设计

4.1 Session 抽层（transport-agnostic）

将当前 frame.Handler 中与传输耦合的 net.Conn 抽离，业务逻辑迁移到独立的 Session 结构体：

// frame/session.go（新增）
type Session struct {
    svcCtx   *svc.ServiceContext
    deviceID string
    tenantID int64
    zoneID   string
    authed   bool
    source   string  // "tcp-gateway" | "coap-gateway"
}

// HandleFrame 处理单帧，返回响应与是否保持会话
func (s *Session) HandleFrame(ctx context.Context, f *Frame) (Response, bool)

// TCP 适配层：bufio 读帧 + 写回 conn
type TCPHandler struct { sess *Session; conn net.Conn }

// CoAP 适配层：UDP 请求 → Frame → HandleFrame → 响应写回
type CoAPHandler struct { sess *Session }

六、验收标准

  • ☐ CoAP.Enabled=true 时 UDP 5683 可接收设备 auth+telemetry/event/status/ack，行为与 TCP 一致（同 Session）
  • ☐ 上报消息进入 device-telemetry，告警类进入 alarm-event，tenant_id/zone_id 正确充入
  • ☐ ack 正确回写 command_log 终态
  • ☐ CoAP.Enabled=false 时服务不监听 CoAP 端口，TCP 行为零回归
  • ☐ protocol_test.go 覆盖 Session.HandleFrame 全帧类型
  • ☐ CoAP 集成测试通过（coap client 模拟设备全流程）
  • ☐ DTLS 5684 生产路径经联调验证

风险缓解
