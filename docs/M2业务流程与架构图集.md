# M2 物业管理服务模块 · 业务流程图与架构图集

> **模块名称：** M2 物业管理服务（Property Service）
> **适用范围：** `app/workorder-service`、`app/visitor-service`、`app/parking-service`、`app/notice-service`
> **对齐依据：** `docs/M2物业管理服务模块设计文档.md`（V1.1）、`docs/M2网关路由与端口清单.md`、各服务 `.api` 契约、`internal/state/fsm.go`、`common/kafka/topics.go`
> **更新时间：** 2026-09-15
> **渲染说明：** 本文所有图均为 Mermaid 语法，可在 IDE / GitHub / VS Code（Markdown Preview Mermaid Support）中直接渲染。

> ⚠️ **状态机口径说明**：本图集以**代码实际实现**为准 —— 工单 FSM 为 5 态 `待派单(0) → 处理中(1) → 待验收(2) → 已完成(3) → 已关闭(4)`；设计文档正文中残留的"待受理 / 已驳回 / 已取消"为已合并的旧口径（建单即待派单、驳回回到处理中、取消即 close）。

## 三、流转图（状态机）

### 3.1 工单状态机（5 态，`internal/state/fsm.go` 实现口径）

```mermaid
stateDiagram-v2
    [*] --> 待派单 : 建单 create（status=0, version=0）
    待派单 --> 处理中 : assign 派单（分配 assignee_id + department_id）
    处理中 --> 待验收 : submit 提交完成
    待验收 --> 已完成 : approve 验收通过（写 finished_at）
    待验收 --> 处理中 : reject 驳回
    已完成 --> 已关闭 : close 关闭（写 finished_at）
    待派单 --> 已关闭 : close 取消
    处理中 --> 已关闭 : close 取消
    已关闭 --> [*]

    note right of 待派单
        transitions 表：
        0 → assign → 1
        0 → close  → 4
    end note
    note right of 待验收
        2 → approve → 3
        2 → reject  → 1
        2 → close   → 4
    end note
    note left of 已关闭
        终态 4，无任何出边
        IsTerminal(4) = true
    end note
```

**FSM 转移表（与代码逐条对应）**

| from 状态 | action | to 状态 | 说明 |
| --- | --- | --- | --- |
| 待派单(0) | `assign` | 处理中(1) | 派单，同时写 `assignee_id`/`department_id` |
| 待派单(0) | `close` | 已关闭(4) | 取消工单 |
| 处理中(1) | `submit` | 待验收(2) | 维修提交完成 |
| 处理中(1) | `close` | 已关闭(4) | 取消工单 |
| 待验收(2) | `approve` | 已完成(3) | 验收通过，写 `finished_at` |
| 待验收(2) | `reject` | 处理中(1) | 驳回，回到处理中 |
| 待验收(2) | `close` | 已关闭(4) | 取消工单 |
| 已完成(3) | `close` | 已关闭(4) | 归档关闭 |

> 并发控制：所有流转均带 `WHERE id=? AND tenant_id=? AND version=?`，`RowsAffected==0` 即视为并发冲突，返回"请刷新后重试"。

## 四、时序图

### 4.1 工单主流程：建单 → 派单 → 提交 → 验收（含乐观锁与事件）

```mermaid
sequenceDiagram
    autonumber
    participant U as 业主/APP
    participant GW as gateway(8080)
    participant WO as workorder-service(8091)
    participant MW as common/middleware.Tenant
    participant FSM as internal/state FSM
    participant DB as MySQL workorder_db
    participant KQ as Kafka workorder-event
    participant CS as 客服/管理后台
    participant MT as 维修人员

    Note over U,GW: ① 建单
    U->>GW: POST /api/workorder<br/>{type,title,description,priority,location}
    GW->>GW: 注入 x-request-id / x-tenant-id / x-user-id / x-role-ids
    GW->>WO: 反向代理转发
    WO->>MW: 中间件写 ctxdata
    MW-->>WO: ctxdata.GetTenantId() / GetUserId()
    WO->>WO: 生成工单号 WO-YYYYMMDD-XXXX
    WO->>DB: INSERT work_order (status=0 待派单, version=0)
    WO->>DB: INSERT work_order_flow (from=-1, action="create")
    WO-)KQ: publish event="created"
    WO-->>GW: {code:"0", data:{id,order_no,status:0}}
    GW-->>U: 200 统一响应体

    Note over CS,DB: ② 派单（乐观锁）
    CS->>GW: PUT /api/workorder/:id/assign {assignee_id, department_id}
    GW->>WO: 转发
    WO->>DB: SELECT WHERE id=? AND tenant_id=?
    DB-->>WO: 工单（status=0, version=v）
    WO->>FSM: NextStatus(0, "assign") → 1
    FSM-->>WO: ok
    WO->>DB: UPDATE SET assignee_id, department_id, status=1,<br/>version=version+1 WHERE id=? AND tenant_id=? AND version=v
    alt RowsAffected == 0
        WO-->>CS: 派单冲突，请刷新后重试（M2-E-1xxx）
    else 更新成功
        WO->>DB: INSERT work_order_flow (0→1, "assign")
        WO-)KQ: publish event="assigned"
        WO-->>CS: {id, order_no, status:1}
    end

    Note over MT,DB: ③ 提交完成
    MT->>GW: PUT /api/workorder/:id/status {action:"submit"}
    GW->>WO: 转发
    WO->>FSM: NextStatus(1, "submit") → 2
    WO->>DB: 乐观锁更新 status=2 + 写流水
    WO-)KQ: publish event="status_changed" (1→2)
    WO-->>MT: {status:2 待验收}

    Note over U,DB: ④ 验收
    alt 验收通过
        U->>WO: PUT /api/workorder/:id/status {action:"approve"}
        WO->>FSM: NextStatus(2,"approve") → 3
        WO->>DB: 更新 status=3, finished_at=now + 流水
        WO-)KQ: publish event="status_changed" (2→3)
    else 驳回
        U->>WO: PUT /api/workorder/:id/status {action:"reject", remark:"重做"}
        WO->>FSM: NextStatus(2,"reject") → 1
        WO->>DB: 更新 status=1 + 流水（带 remark）
        WO-)KQ: publish event="status_changed" (2→1)
    end

    Note over KQ: M5 大屏 / 通知类服务订阅消费，感知工单变化
```

### 4.2 访客邀请 + 扫码签入（含 M1 开门与降级）

```mermaid
sequenceDiagram
    autonumber
    participant O as 业主/物业
    participant V as 访客
    participant GW as gateway(8080)
    participant VI as visitor-service(8092)
    participant DB as MySQL visitor_db
    participant M1 as M1 device-service gRPC(9001)

    Note over O,DB: ① 发起邀请
    O->>GW: POST /api/visitor/invite<br/>{visitor_name,visitor_phone,visit_time,expire_time,reason}
    GW->>VI: 转发（注入 tenant_id / user_id）
    VI->>VI: genQRCode → base64(JSON载荷 + md5签名)<br/>签名=md5(tenant|inviter|visitor|expire|salt)
    VI->>DB: INSERT visitor_record (status=1 待使用, qr_code)
    VI-->>O: {id, qr_code, expire_at}
    O-->>V: 二维码下发访客

    Note over V,M1: ② 门岗扫码签入
    V->>GW: POST /api/visitor/checkin {qr_code}
    GW->>VI: 转发
    VI->>DB: SELECT WHERE qr_code=? AND tenant_id=?
    alt 记录不存在
        VI-->>V: 二维码无效
    else 已过期
        VI->>DB: UPDATE status=4 已过期
        VI-->>V: 二维码已过期
    else 已签入/已签出
        VI-->>V: 二维码已被核销
    else 校验通过
        VI->>DB: UPDATE status=2 已签入, checkin_at=now
        opt DeviceRPC 已配置且 Door.DeviceID 非空
            VI->>M1: SendCommand{device_id, command:"open_door"}<br/>（context 800ms 短超时）
            alt 开门成功
                M1-->>VI: CommandResult{device_id}
                VI->>DB: UPDATE device_id 回填
            else M1 不可达 / 超时
                Note over VI: 降级：仅记 error 日志，不阻断签入
            end
        end
        VI-->>V: {id, status:2, checkin_at, device_id?}
    end

    Note over V,DB: ③ 签出
    V->>GW: POST /api/visitor/checkout {id 或 qr_code}
    GW->>VI: 转发
    VI->>DB: UPDATE status=3 已签出, checkout_at=now
    VI-->>V: {id, status:3, checkout_at}
```

### 4.3 停车入场（Kafka 地磁事件驱动）

```mermaid
sequenceDiagram
    autonumber
    participant DEV as 地磁/车牌识别设备
    participant EMQX as EMQX MQTT
    participant M1 as M1 event-dispatcher
    participant KQ as Kafka device-telemetry
    participant PA as parking-service(8093)
    participant DB as MySQL parking_db
    participant OUT as Kafka parking-entry

    DEV->>EMQX: 设备遥测上报（车牌 + 地磁状态）
    EMQX->>M1: 消息投递
    M1->>KQ: produce topic=device-telemetry<br/>{tenant_id, device_id, event:"entry", plate_no, vehicle_type, timestamp}
    KQ->>PA: 消费组 parking-service 拉取
    PA->>PA: json.Unmarshal → deviceTelemetry
    alt 消息格式非法
        PA->>PA: 记 warn 日志并跳过（不阻塞后续消费）
    else event == "entry"
        PA->>DB: INSERT parking_record<br/>(status=1 停车中, entry_time=now, device_id_in)
        PA-)OUT: publish parking-entry (key=plate_no)
    else event == "exit"
        PA->>PA: onTelemetryExit（见 4.4）
    else 未知 event
        PA->>PA: 记 warn 日志并跳过
    end
```

### 4.4 停车离场计费

```mermaid
sequenceDiagram
    autonumber
    participant KQ as Kafka device-telemetry
    participant PA as parking-service
    participant DB as MySQL parking_db
    participant FEE as svc.CalcFee
    participant K1 as Kafka parking-exit
    participant K2 as Kafka alarm-event
    participant M3 as M3 安防

    KQ->>PA: {event:"exit", plate_no, device_id, tenant_id}
    PA->>DB: SELECT WHERE plate_no=? AND tenant_id=? AND status=1<br/>ORDER BY id DESC LIMIT 1
    alt 无在场记录
        PA->>PA: 记 warn "exit but no active record"，直接结束

        Note over FEE: 月卡/VIP → 0<br/>临时车 ≤15min → 0<br/>超出 → 5 元/小时（向上取整）

        PA-)K1: publish parking-exit (key=plate_no)
        alt vehicle_type == 4 异常车
            PA-)K2: publish alarm-event {severity:2, content:"异常车辆 X 离场"}
            K2-)M3: 安防联动消费
        end
    end

    Note over PA: HTTP 联调等价路径：<br/>POST /api/parking/exit {plate_no, device_id_out} → 同一段计费逻辑
```

### 4.7 请求统一入口：网关鉴权与上下文注入链

```mermaid
sequenceDiagram
```
