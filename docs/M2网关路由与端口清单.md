# M2 网关路由与端口清单

> 适用模块：M2 物业管理服务（workorder / visitor / parking / notice / billing）
> 关联：M5 运营大屏（leasing / dashboard / dispatch）
> 网关实现：根目录 `gateway/`（模块 `onepark/gateway`），对外端口 **8080**
> 更新时间：2026-09-15

## 一、网关说明

`gateway/` 是 OnePark 对外统一 HTTP 入口（`:8080`），采用**前缀反向代理**模式：

- 按 `etc/apigateway-api.yaml` 中 `Upstreams` 配置的**最长前缀**匹配，转发到对应业务服务；
- 转发前注入/透传上下文头：`x-request-id`、`x-tenant-id`、`x-user-id`、`x-role-ids`；
- 统一 CORS；上游不可用时返回 502 统一响应体 `{code:"M6-E-0006",msg,data:null}`。

> 注意区分：`gateway/` 是对前端/管理端的 HTTP 对外入口；`app/gateway-service/` 是 M1 面向设备的 TCP/CoAP 接入网关（`:7000`），两者不同。

配置文件：`gateway/etc/apigateway-api.yaml`

```yaml
Name: apigateway-api
Host: 0.0.0.0
Port: 8080
DefaultTenantId: 1        # 无鉴权联调默认园区ID(生产由 M6 注入 x-tenant-id 覆盖)
Upstreams:
  - Prefix: /api/workorder
    Target: http://127.0.0.1:8091
  - Prefix: /api/visitor
    Target: http://127.0.0.1:8092
  - Prefix: /api/parking
    Target: http://127.0.0.1:8093
  - Prefix: /api/notice
    Target: http://127.0.0.1:8094
  # billing(M2 计费): P1 补租户隔离后接入网关, 与 M2 其它服务同链路注入 x-tenant-id
  - Prefix: /api/billing
    Target: http://127.0.0.1:8063
  - Prefix: /api/leasing
    Target: http://127.0.0.1:8015
  - Prefix: /api/dashboard
    Target: http://127.0.0.1:8016
  - Prefix: /api/dispatch
    Target: http://127.0.0.1:8017
```

## 二、端口与路由前缀清单

| 服务 | 进程内网 HTTP | 网关前缀 | 所属模块 |
| --- | --- | --- | --- |
| workorder-service | 8091（gRPC 9091） | `/api/workorder`、`/api/workorders` | M2 |
| visitor-service | 8092 | `/api/visitor`、`/api/visitors` | M2 |
| parking-service | 8093 | `/api/parking` | M2 |
| notice-service | 8094 | `/api/notice`、`/api/notices` | M2 |
| billing-service | 8063 | `/api/billing` | M2 |
| leasing-service | 8015 | `/api/leasing` | M5 |
| dashboard-service | 8016 | `/api/dashboard` | M5 |
| dispatch-service | 8017 | `/api/dispatch` | M5 |

> 前缀匹配规则：`/api/workorder` 同时覆盖 `/api/workorders`（列表）与 `/api/workorder/:id`（详情）；
> `/api/visitor` 覆盖 `/api/visitors`；`/api/notice` 覆盖 `/api/notices`。故上表已可覆盖全部接口，无需逐条登记。

## 三、M2 全部 15 个接口（经网关访问）

### 1. workorder-service（→ 8091，前缀 `/api/workorder`）
| # | 方法 | 网关路径 | 说明 |
| --- | --- | --- | --- |
| 1 | POST | `/api/workorder` | 创建工单（建单即待派单） |
| 2 | PUT | `/api/workorder/:id/assign` | 派单（待派单→处理中，乐观锁） |
| 3 | PUT | `/api/workorder/:id/status` | 状态流转（submit/approve/reject/close） |
| 4 | GET | `/api/workorder/:id` | 工单详情 |
| 5 | GET | `/api/workorders` | 工单分页列表（需 `page`、`page_size`） |

### 2. visitor-service（→ 8092，前缀 `/api/visitor`）
| # | 方法 | 网关路径 | 说明 |
| --- | --- | --- | --- |
| 6 | POST | `/api/visitor/invite` | 访客邀请，生成二维码 |
| 7 | POST | `/api/visitor/checkin` | 扫码签入（核销 + 调 M1 开门 + 回填 device_id） |
| 8 | POST | `/api/visitor/checkout` | 访客签出 |
| 9 | GET | `/api/visitors` | 访客记录分页（需 `page`、`page_size`） |

### 3. parking-service（→ 8093，前缀 `/api/parking`）
| # | 方法 | 网关路径 | 说明 |
| --- | --- | --- | --- |
| 10 | POST | `/api/parking/entry` | 车辆入场（发 parking-entry 事件） |
| 11 | POST | `/api/parking/exit` | 车辆离场（计费 + 发 parking-exit 事件） |
| 12 | GET | `/api/parking/records` | 停车记录分页（需 `page`、`page_size`） |
| 13 | GET | `/api/parking/active` | 在场车辆列表 |

### 4. notice-service（→ 8094，前缀 `/api/notice`）
| # | 方法 | 网关路径 | 说明 |
| --- | --- | --- | --- |
| 14 | POST | `/api/notice` | 发布公告（发 notice-event 事件） |
| 15 | GET | `/api/notices` | 公告分页列表（需 `page`、`page_size`） |

> 除上述 15 个 HTTP 接口外，M2 另有 1 个 gRPC 接口 `WorkorderService.ListWorkOrders`（`:9091`，供 M5 大屏聚合），不经网关。

## 四、请求头约定（网关注入）

| Header | 含义 | 缺省 |
| --- | --- | --- |
| `x-request-id` | 全链路追踪 ID | 网关生成并回写响应头 |
| `x-tenant-id` | 园区/租户 ID（RBAC 数据隔离） | `DefaultTenantId`（默认 1） |
| `x-user-id` | 用户 ID | `DefaultUserId`（默认 0） |
| `x-role-ids` | 角色 ID 列表（逗号分隔） | 空 |

业务服务侧由 `common/middleware.Tenant` 中间件写入 `common/ctxdata`，logic 层通过 `ctxdata.GetTenantId/GetUserId/GetRoleIds` 读取。

## 五、验证

```bash
# 1) 起服务(M2 四服务 + billing + M5 三服务 + 网关)
powershell -ExecutionPolicy Bypass -File ..\start-onepark.ps1

# 2) 经网关访问 M2 接口
curl -i http://localhost:8080/api/workorders?page=1\&page_size=10 -H "x-tenant-id: 1"
curl -i http://localhost:8080/api/visitor/checkin -X POST -H "Content-Type: application/json" -H "x-tenant-id: 1" -d '{"qr_code":"..."}'

# 3) 经网关访问 M5 大屏
curl -i http://localhost:8080/api/dashboard/overview -H "x-tenant-id: 1"
```

预期：请求被正确转发到对应服务；上游不可用时返回 `502 {code:"M6-E-0006"}`；未匹配前缀返回 `404 {code:"M6-E-0004"}`。

## 六、与成员 2 的协作点

1. **路由表**：只需在 `gateway/etc/apigateway-api.yaml` 的 `Upstreams` 增删条目即可扩缩容，无需改代码。
2. **鉴权（M6）**：网关当前为无鉴权联调模式（`DefaultTenantId` 兜底）。接入 M6 `ValidateToken/CheckPermission` 后，应由鉴权中间件按 Token 解析并注入 `x-user-id`/`x-role-ids`/`x-tenant-id`，覆盖默认值。
3. **限流**：可在网关增加 `common/middleware` 限流中间件（按租户/接口）。
