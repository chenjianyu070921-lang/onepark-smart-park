## 结论

**22 / 22 个 module 全部编译通过（0 失败）。**

## 背景：为什么不是字面的 `go build ./...`

仓库是多 module workspace（`go.work`，共 22 个 module：`common`、`proto`、`gateway` + `app/` 下 19 个服务），
**根目录没有 `go.mod`**。因此：

```text
$ go build ./...            # 在根目录执行
pattern ./...: directory prefix . does not contain modules listed in go.work or their selected dependencies
```

正确做法是**逐 module** 编译（`make build-all` 已封装此逻辑，供 Linux/CI 使用）：

```powershell
$mods = @('common','gateway','proto') + (Get-ChildItem app -Directory | % { "app\$($_.Name)" })
foreach ($m in $mods) { Push-Location $m; go build ./...; Pop-Location }   # 任一失败即需修复
```

## 本次修复的 2 处编译错误（根因）

### 1. `app/parking-service`（3 处）
- `internal/svc/consumer.go`：`deviceTelemetry` 结构体丢失标准信封字段
  `DeviceID / EventType / OccurredAt / Payload`，但 `normalizeTelemetry` / `IdempotentID` 仍在引用
  → **恢复缺失字段**（保留原有扁平字段作向后兼容）。
- 同文件 `handleTelemetry`：把原始消息解进 `t` 后又写 `t := normalizeTelemetry(&raw)`，
  `raw` 未定义且 `t` 重复声明 → 改为 `var raw deviceTelemetry` 解入 `&raw`，再 `t := normalizeTelemetry(&raw)`。
- 同文件 `onTelemetryEntry`：引用了未定义的 `eventTime`
  → 补 `entryTime := time.Unix(t.Timestamp, 0)`（与离场 `exit` 的事件时间口径一致）。

### 2. `app/dispatch-service`（1 处）
- `internal/cron/expire.go:111` 使用 `state.ActionExpire`，但 `state` 包未定义该常量
  → 在 `internal/state/fsm.go` 补 `ActionExpire = "expire"`，并补状态转移边
  `StatusAssigned --ActionExpire--> StatusPendingAssign`（动作语义与 `ActionRelease` 相同，但触发源不同：超时 vs 主动释放）。
