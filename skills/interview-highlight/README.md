# interview-highlight 使用说明

> 面试亮点讲解生成器 —— 把"做过但讲不清"的模块，变成面试能脱稿讲清、被追问也接得住的亮点

## 一、这是什么

`interview-highlight` 是面向实训学生求职准备的 CodeBuddy 技能。指定当前项目里的任意模块，它会：

1. **先读真实代码**：通读该模块的代码、契约、测试与配置，提取真实机制与参数——不是凭空编故事；
2. **生成第一人称讲解稿**：需求背景 → 技术难点 → 业务难点 → 解决方案 → 优化成果 → 测试与质量保障，口语化、去 AI 味、可直接背诵，用于面试讲"项目亮点"；
3. **预测面试官追问**：按五层深度（概念→实现→原理→对比→权衡）生成 10-15 个追问，每问附第一人称参考答案与二次追问提示，保证被追问时不会因"完全没听过"而失败。

## 二、适用范围

| 场景 | 是否使用 |
|---|---|
| 毕业求职 / 实习面试前的项目亮点准备 | ✅ 核心场景 |
| 月度答辩、周答辩的"亮点功能"话术打磨 | ✅ 可用 |
| 模拟面试出题（互相提问） | ✅ 可用 |
| 写代码、修 bug（开发类任务） | ❌ 请用 dev-quality-guard |

**触发方式**：安装后在项目内显式调用（推荐，可精确指定模块）：

```
/interview-highlight 订单服务的分布式锁防并发
/interview-highlight 商品热点缓存三重防护
/interview-highlight Redis GEO 派单引擎
```

## 三、安装与分发

1. 拿到 `interview-highlight.zip`，解压；
2. 将 `interview-highlight` 文件夹放入：
   - 个人使用：`C:\Users\<用户名>\.codebuddy\skills\`
   - 团队共享：项目根目录 `.codebuddy/skills/`
3. 重启 CodeBuddy（或新开会话）生效。

## 四、产出物说明

运行后在项目内生成 `docs/interview/<模块名>-亮点讲解.md`，包含三部分：

| 部分 | 内容 | 用法 |
|---|---|---|
| 一、亮点讲解稿 | 3-5 分钟口播稿，六段结构：需求背景 / 技术难点 / 业务难点 / 解决方案 / 优化成果 / 测试与质量保障（含公司测试目标与达标手段） | 面试主答，需背熟 |
| 二、面试官追问预测 | 10-15 个分层追问，每问附第一人称参考答案（100-250 字）+ 可能的二次追问 | 逐题学懂，不是背诵 |
| 三、面试前 3 分钟速记卡 | 核心数字 + 一句话亮点 + 最容易被问的 3 个问题 | 面试候场快速过一遍 |

**内容可信度边界（重要）**：

- 机制、参数、设计**全部来自当前项目真实代码**，学了就能对上自己的仓库；
- 成果数据允许合理拔高（性能提升、成功率、并发量），但必须满足三条：量级与项目规模匹配、数字之间自洽、被追问时能圆回来；
- 禁止虚构不存在的架构——因为面试官一追问原理，编的东西一定露馅。

## 五、写作风格保证（去 AI 化）

技能内置硬性风格约束，产出稿不会带"AI 味"：

- 第一人称"我"，口语短句，可用"当时 / 后来 / 踩了个坑"；
- 禁用"首先/其次/总之/值得注意的是/赋能"等 AI 高频词，禁排比句与对仗小标题；
- 每篇必含具体数字（阈值、耗时、成功率、并发量）+ 至少一个"踩坑→定位→修复→验证"故事。

## 六、教师管理用法

1. **就业课作业**：要求每人对自己的核心模块出一份亮点讲解稿，纳入就业考核材料；
2. **模拟面试**：教师直接拿"追问预测"部分当题库，现场提问检验学生是否真学懂；
3. **配合 dev-quality-guard 使用**：开发阶段用 dev-quality-guard 保证代码真实、可讲解；求职阶段用本技能把真实代码转成面试话术——两步都建立在"代码是自己能讲清的"之上；
4. **材料归档**：`docs/interview/` 随 Git 仓库提交，可追溯学生求职准备过程。

## 七、常见问题

**Q1：不装在项目里、只给一段代码能用吗？**
推荐在完整项目内使用（技能会读整个模块上下文，产出更真实）；只有零散代码片段时也可用，但成果数据要自己再校准。

**Q2：生成的数字能直接用吗？**
讲解稿里的成果数据是在真实代码基础上合理拔高的。要求学生：先用压测实测一次，用实测值替换或校准——既真实又有底气。

**Q3：和直接让 AI"帮我写个面试自我介绍"有什么区别？**
直接问只会得到一篇书面腔的稿子，追问就露馅。本技能强制：读真实代码 → 口语化讲解稿 → 分层追问全覆盖，目标是"被追问也接得住"，而不是"一篇稿子"。

**Q4：可以调整追问深度或题库吗？**
可以。编辑 `references/question-framework.md`（五层框架 + 11 类机制题库）即可；建议按目标公司技术栈增删题库条目。
