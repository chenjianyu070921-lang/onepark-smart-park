# 面试官追问五层框架与机制题库

第三步的执行依据。按五层框架组织追问，再按模块命中的机制从题库中挑条目深挖。每个追问最终都要展开成第一人称口语参考答案。

## 一、五层追问框架（每层 2-3 问，共 10-15 问）

### 第 1 层：概念层——是什么、为什么
- 这个功能解决什么问题？没有它会怎样？
- 它的业务价值怎么衡量？
- 你在其中的角色和产出是什么？

### 第 2 层：实现层——怎么做的
- 整体流程怎么走？能不能画个时序图？
- 关键表结构 / 数据结构怎么设计的？为什么这么设计？
- 核心代码是怎么组织的？哪一段最关键？

### 第 3 层：原理层——底层与极端场景
- 它依赖的底层机制是什么（如 Lua 脚本原子性、singleflight 原理、Redis GEO 的底层结构）？
- 性能瓶颈在哪？你怎么定位的？
- 极端场景会怎样：服务宕机、并发洪峰、数据不一致、重复请求？

### 第 4 层：对比层——为什么不用 X
- 为什么不用 <替代方案 A>？对比过哪些方案？
- 如果流量再大 10 倍，这套方案还扛得住吗？要改哪里？
- 开源现成方案那么多，为什么要自己（这样做）？

### 第 5 层：权衡层——代价与反思
- 这套方案的代价是什么（复杂度/成本/一致性）？
- 上线后出过什么问题？怎么发现、怎么解决的？
- 如果重新做一遍，你会怎么改进？

## 二、常见机制追问题库（命中哪个机制就深挖哪组）

### 1. 缓存（穿透/击穿/雪崩、预热、一致性）
- 缓存和数据库一致性怎么保证？先删缓存还是先更新库？延迟双删用过吗？
- 空值占位的时间为什么定 5 分钟？定长了会怎样？
- 回填锁的释放失败怎么办？singleflight 的原理是什么，和分布式锁什么区别？
- TTL 为什么要加随机抖动？抖动范围怎么定的？
- 预热脚本失败了怎么办？预热的数据更新了怎么办？

### 2. 限流（令牌桶、Lua、分布式限流）
- 令牌桶和漏桶的区别？为什么选令牌桶？
- Lua 脚本为什么能保证原子？不用 Lua 会出什么问题？
- 多实例部署时限流阈值怎么共享？Redis 挂了限流还生效吗？
- 限流阈值怎么定的？突发流量和持续流量怎么分别处理？
- 被限流的请求怎么处理？直接拒绝还是排队？返回什么？

### 3. 分布式锁（SetNX、token+Lua、看门狗、续期）
- 为什么裸 SetNX 不行？锁误删怎么发生？
- token + Lua 释放的流程？看门狗续期周期怎么定？
- 锁超时了业务还没执行完怎么办？Redis 主从切换锁丢了怎么办？
- 和数据库乐观锁/悲观锁比，什么场景该用哪个？
- 看门狗的原理你清楚吗？自己实现要怎么做？

### 4. 消息队列（Kafka 可靠性、顺序、重复、堆积）
- 消息丢了怎么办？生产者、Broker、消费者三段分别怎么保证？
- 重复消费怎么办？幂等怎么落地？
- 消息堆积了怎么处理？扩分区有用吗？
- 顺序性怎么保证？分区键怎么选？
- 为什么用 Kafka 不用 RabbitMQ/RocketMQ？

### 5. 分布式事务（TCC、本地消息表、延迟队列补偿）
- TCC 三个阶段各自做什么？Cancel 空回滚怎么办？
- 本地消息表和事务消息的区别？为什么选本地消息表？
- 补偿一直失败怎么办？最终一致的窗口期业务上能接受吗？
- 和 Seata 比为什么不用/用？
- 库存扣减和优惠券核销怎么保证一起成功？

### 6. 数据库（索引、分库分表、慢查询）
- 这个索引用 explain 怎么证明有效？type 和 rows 看什么？
- 为什么这个查询不走索引？函数处理/隐式转换/最左前缀举例说说。
- 分库分表怎么分的？分片键怎么选？跨片查询怎么办？
- 慢查询怎么治理？你们慢 SQL 阈值多少？
- 大表加字段/加索引怎么操作才不锁表？

### 7. 状态机 / 订单流转
- 状态机有几种实现方式（枚举校验/表驱动/状态机框架）？你为什么这么选？
- 非法流转怎么拦截？并发下单/取消怎么保证状态一致？
- 状态流水表记什么？为什么不直接改状态字段？
- 超时未支付的订单怎么关闭？延迟队列还是定时任务，为什么？

### 8. 认证与安全（JWT 双 Token、刷新轮换、黑名单、越权）
- 双 Token 怎么配合？access 泄露了危害窗口多大？
- refresh 轮换是什么？旧 refresh 还能用吗，怎么保证？
- 登出怎么立即失效？黑名单存什么、TTL 怎么定？
- 越权漏洞怎么防？举个你自测的例子。
- 密码为什么用 bcrypt 不用 MD5？手机号为什么哈希存？

### 9. 微服务治理（etcd、gRPC、超时重试熔断降级）
- 为什么服务注册用 etcd 不用 Nacos/Consul？etcd 的 lease 机制说说。
- gRPC 为什么快？和 REST 比什么时候反而慢？
- 超时、重试、熔断的参数怎么定？重试会不会放大雪崩？
- 服务雪崩是怎么发生的？你的降级策略是什么？
- 链路追踪怎么做的？trace_id 怎么串起来的？

### 10. AI 应用（RAG、向量检索、意图识别、多轮对话）
- RAG 的完整流程？召回和重排的区别？
- 向量库选型为什么是它？embedding 模型怎么选的？
- 意图识别准确率怎么评估的？badcase 怎么治理？
- 多轮对话的上下文怎么管理？超长怎么截断？
- 幻觉问题怎么缓解？

### 11. 测试与质量保障（压测、单测、上线标准）
- 你们的测试目标/质量门槛是什么（覆盖率、P99、错误率）？达不到怎么办？
- 压测怎么做的？工具、并发模型、加压策略？压测环境怎么搭？
- 单测怎么写才算好？mock 什么、不 mock 什么？
- 上线前 checklist 有哪些？回滚方案是什么？
- 线上出问题怎么定位？日志、监控、链路追踪怎么配合？

## 三、出题要求

1. 追问必须"有层次、能深挖"：同一机制先问做法，再问原理，再问极端场景。
2. 参考答案必须包含：结论 + 原因 + 细节/数字 + 一个例子；口语化，禁止书面腔。
3. 每个参考答案末尾标注"可能的二次追问"及一句话答题方向。
4. 覆盖用户真实弱项：凡讲解稿里提到的机制，至少出 1 道原理层追问，防止"没听过导致答不上"。
