# 理解验证题出题角度库

第 2 步的执行依据。按本次代码命中的机制挑角度组题。**每道题必须绑定本次代码的具体细节**（某行、某参数、某表、某接口），禁止通用八股题。

## 一、通用四种角度（每轮至少覆盖三种）

1. **原理题**：这个机制为什么这么用？换成 X 会怎样？
2. **代码题**：第 N 行的作用是什么？删掉它 / 交换顺序会怎样？
3. **边界题**：100 个请求同时进来会怎样？超时了？重复请求？
4. **修改题（每轮必出 1 道）**：现在要求改成 <小变更>，要动哪里？影响什么？

出题时把角度套到本次代码的具体细节上，例：
- ❌ 通用八股："分布式锁有什么用？"
- ✅ 绑定细节："你这把锁的 key 是 `lock:order:{orderID}`，为什么必须带 orderID？不带会发生什么？"

## 二、按机制的专属出题角度

### 分布式锁
- 锁 key 为什么带业务 id？粒度太粗/太细各有什么问题？
- token + Lua 释放为什么必要？误删别人的锁会怎么发生（说清时序）？
- 看门狗续期周期是多少？改短/改长分别会怎样？
- Redis 挂了，锁还在吗？业务走哪条路径？

### 事务与一致性（本地消息 / TCC / 补偿）
- 消息表和业务表为什么必须在同一个事务里？拆开会丢什么？
- 补偿重试几次？一直失败谁兜底（人工/告警）？
- 空回滚、悬挂怎么防（事务ID 判断）？
- 这段代码里哪一步失败会造成资损？为什么不会？

### 缓存
- 空值占位 TTL 为什么是这个值？定长了有什么副作用？
- 回填锁拿不到的请求走哪条降级路径？
- 先更新库还是先删缓存？不一致窗口多大？业务能接受吗？
- 预热数据更新后，缓存怎么失效？谁负责删？

### 鉴权与双 Token
- access 泄露的危害窗口多大？refresh 怎么缩小它？
- 黑名单存什么 key、TTL 怎么定的？为什么是这个值？
- 刷新接口为什么不能用 access 鉴权？会不会被刷？怎么防？

### 消息队列
- 消费失败重回队列会不会无限循环？重试次数与死信在哪配置？
- 重复消费怎么幂等？幂等 key 用的什么字段？
- 顺序性靠什么保证（分区键）？换一个键会乱吗？

### 数据库
- 这条 SQL 走哪个索引？explain 里看什么字段确认？
- 为什么不用 JOIN / 为什么拆成两条？
- 循环里这条查询改成批量后，省了多少次往返？怎么算的？

### 状态机与定时任务
- 非法流转在哪里被拦？为什么集中拦截而不是散在各接口？
- 扫描间隔与单次数据量怎么匹配？数据涨 10 倍会怎样？
- 两台实例同时跑这个定时任务会怎样？怎么防？

### 限流
- 令牌桶参数（rate/burst）怎么定的？突发 2 倍流量会怎样？
- Lua 脚本里如果先 GET 后 SET 会出什么问题？
- 被拒请求返回什么？前端怎么感知？

### 跨服务调用
- 超时为什么定这个值？对方 P99 是多少？
- 重试几次？会不会放大故障（重试风暴）？
- 对方挂了，这段代码走哪条降级路径？降级后果业务能接受吗？

## 三、测试类产出的专属角度（单测 / 并发用例 / 压测脚本过闸门）

- 这条断言在验证什么？把它删了测试还能过吗——说明了什么问题？
- 你的用例覆盖了哪些场景？哪三类场景没覆盖？为什么可以不覆盖？
- mock 了什么、没 mock 什么？被 mock 掉的部分出问题，这个测试还可靠吗？
- 压测的并发模型怎么设计的（匀速/阶梯/脉冲）？为什么这样加压？
- P99 是怎么采样计算的？样本量够不够支撑结论？
- 修改题：现在要新增 XX 异常场景的用例 / 并发从 100 提到 1000，要改哪里？哪些断言会先挂？

## 四、优化类产出的专属角度（性能优化改动过闸门）

- 瓶颈是怎么定位的？证据是什么（profile / explain / 监控曲线）？没有证据的优化先打回。
- 优化前后指标对比（耗时 / QPS / 内存）？提升幅度怎么算的？
- 这个优化有没有副作用（一致性风险 / 可读性下降 / 极端场景行为变化）？
- 为什么这个方案比 XX 方案好？当时还考虑过什么？
- 修改题：数据量涨 10 倍后，这个优化哪里先失效？下一步优化方向是什么？

## 五、修改题出题模板（每轮必出）

- "现在要求把 XX 超时从 3 秒改成 5 秒 / 增加一个 XX 字段 / 支持批量 XX"——要改哪几处？各处影响什么？
- "线上出现 XX 现象（超时突增 / 重复扣减 / 缓存不一致），用这段代码解释可能原因，说出排查步骤"
- "明天流量涨 10 倍，这段代码哪一行先扛不住？怎么改？"

## 六、评判要点

- **意思到位即通过**：不追求措辞，能说出"为什么"至少一层就算对；
- **修改题必须答出**：改哪些位置 + 波及面（下游接口/缓存/数据）；
- **提示梯度**（用户答错时）：先给方向 → 再给框架 → 最多给半句答案，绝不整句给；
- **识别背稿**：回答里出现与本次代码无关的泛泛术语堆砌时，追问一层细节验证。
