# code-explain-gate 使用说明

> AI 代码理解闸门 —— 拦截"AI 写的代码学生不认识"：先过题、再拿码，交付必留讲解卡

## 一、这是什么

`code-explain-gate` 解决实训中最常见的问题：**学生把 AI 生成代码直接粘贴进项目，追问实现原理答不上**（典型：TCC 补偿细节、双 Token 刷新机制讲不透）。

它把"理解验证"放在代码交付**之前**，形成强制闸门：

```
AI 内部生成代码 → 出 3-5 道理解验证题 → 学生先答
    ├─ 答对 → 交付代码 + 《代码讲解卡》
    ├─ 答错 → 只给提示，再考一轮（最多 2 轮）
    └─ 仍不过 → 不交付，给学习材料，标记"待补课"
```

同时，每次闸门的**问答原话**会被记录并自动产出《学情诊断》与累计《学习档案》——学生哪里弱、错在哪、该怎么补，一目了然。

## 二、拦截范围（分级，覆盖开发 / 测试 / 优化全阶段）

### 必须过闸门

| 阶段 | 拦截内容 |
|---|---|
| 开发 | 并发控制（分布式锁/singleflight/扣减/限流）、事务与一致性（本地消息/TCC/乐观锁）、鉴权安全（双 Token/黑名单/越权）、缓存三重防护、消息队列（幂等/重试/顺序）、核心 SQL（分库分表/慢查询）、状态机与定时任务、跨服务调用 |
| 测试 | AI 生成的单元测试与并发用例、压测脚本与压测方案 |
| 优化 | 性能优化改动（SQL/索引/缓存/参数/算法/同步改异步）、核心链路重构 |

### 直接放行

单表 CRUD、DTO/路由/配置、注释文档、前端样式、纯格式调整。

**判定规则**：混合改动只对拦截类部分出题；拿不准按拦截处理。

## 三、安装与分发

1. 拿到 `code-explain-gate.zip`，解压；
2. 将 `code-explain-gate` 文件夹放入：
   - 个人使用：`C:\Users\<用户名>\.codebuddy\skills\`
   - 团队共享：项目根目录 `.codebuddy/skills/`
3. 重启 CodeBuddy（或新开会话）生效。建议与 `dev-quality-guard` 成对安装。

## 四、闸门流程

### 四步流程（开发 / 测试 / 优化通用）

1. **内部生成，暂不交付**——AI 按需求完成编码，但完整代码先不输出；
2. **出理解验证题（3-5 道）**——原理题、代码题、边界题、修改题（每轮必出 1 道），题目绑定本次代码的具体细节，禁止通用八股；
3. **学生作答与评判**——意思到位即通过；答错给梯度提示（方向→框架→半句），最多 2 轮；仍不过不交付，标记"待补课"；
4. **交付与讲解卡**——输出完整代码 + 生成《代码讲解卡》入 `docs/walkthrough/`，与代码同批提交。

### 出题示例（绑定真实代码细节）

- ❌ 通用八股："分布式锁有什么用？"
- ✅ 闸门真题："你这把锁的 key 是 `lock:order:{orderID}`，为什么必须带 orderID？不带会发生什么？"
- ✅ 修改题："把锁超时从 3 秒改成 5 秒，要改哪里？影响什么？"

### 防背稿设计

- 四种角度轮换：为什么这么写 / 删了会怎样 / 需求变了怎么改 / 线上报这个错怎么排查；
- 修改题每轮必出——**能改代码才是理解的证明**；
- 同一模块重考必须换题。

## 五、产出物说明

| 产出物 | 位置 | 用途 |
|---|---|---|
| 代码讲解卡 | `docs/walkthrough/<模块>-<日期>.md` | 学生复习；教师抽查题源；interview-highlight 素材 |
| 学情诊断 | `docs/walkthrough/diagnosis/<模块>-<日期>.md` | 沟通原话留痕 + 五维度问题分析 + 技术提升清单 + 可执行学习建议 |
| 学习档案 | `docs/walkthrough/learning-profile.md` | 累计画像：技术主题红/黄/绿分级、错误集中点、进步曲线——**教师查看学生画像的入口** |

**学情诊断的五维度**：概念盲区 / 实现细节不熟 / 边界与失败场景思维缺失 / 调试排查能力弱 / 表达与结构混乱——每条结论必须引用学生回答原话作证据。

**学习建议的硬标准**：每条必须满足"动作 + 材料 + 验证标准 + 时限"。
- ❌ "加强对分布式锁的学习"（空话，被禁止）
- ✅ "复现锁误删场景：两个 goroutine 模拟 A 超时后 B 抢锁，完成标准是画出误删时序图，2 小时，3 天内完成，重考第 1 题就考这个"

## 六、跨技能出口唯一原则

学生可能同时使用头脑风暴、dev-quality-guard 等其他技能。本技能是**所有代码产出的唯一出口闸门**：

1. 无论当前处于哪个技能的哪个阶段，只要拦截范围内的代码要写入项目，必须先过闸门；
2. 其他技能的"已完成 / 清单全过"只是过程合规，**不是免检凭证**；
3. 非代码产物（规格、背景包、话术）不需要闸门；
4. **没有讲解卡的拦截范围改动 = 未验证交付，答辩与日check 不认可**。

`dev-quality-guard` 已内置第 4 道关与其联动（"出口闸门"），形成闭环。

## 七、教师管理用法

1. **日常**：看 `learning-profile.md` 红/黄项，直接得到"谁、哪块弱、错在哪"的一对一辅导名单；
2. **辅导开场**：用诊断报告里的原话证据（"你当时说……，实际上……"），比空泛批评有效；
3. **答辩抽查**：从讲解卡抽 1 道变形题 + 1 道"现场改需求"——背稿的人当场露馅；
4. **验收规则**：拦截范围改动无讲解卡 = 未验证交付，不记入日check 完成项；
5. **月度复盘**：对比学习档案阶段结论，评估进步曲线、调整分层。

## 八、常见问题

**Q1：学生嫌答题烦，怎么办？**
分级拦截已把摩擦降到最低（CRUD/配置直接放行）。核心代码多答 3-5 题，换来的是答辩和面试不被打穿——这笔账在第一次模拟面试就算得清。

**Q2：学生把题目喂给 AI 代答怎么办？**
对话层防不住，所以锚定在留痕上：讲解卡必须与代码同批提交；答辩用讲解卡之外的变形题 + 现场改需求做终极检验——代答的人过不了"现场改"这一关。

**Q3："待补课"的学生怎么恢复？**
按闸门给出的学习材料自学，完成后主动说"重考"，重新走闸门；重考必换题。学习档案里会记录完整过程。

**Q4：测试、优化的改动也要答题吗？**
是。测试类考断言有效性与场景覆盖缺口，优化类考瓶颈定位证据与效果验证——"压测报告数字漂亮但说不清怎么压的"同样过不了闸门。

**Q5：与 dev-quality-guard 什么关系？**
dev-quality-guard 管流程与质量合规（四阶段、DoD），本技能管每次代码交付的理解验证（它的第 4 道关）。两个一起装、一起用。
