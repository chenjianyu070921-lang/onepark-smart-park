# 提交前自检清单（DoD）

阶段四的执行依据。逐项核对，全部通过才允许提交；任一项不通过，修复后重新自检。

## A. 编译与测试

- [ ] `go build ./...` 通过
- [ ] `go vet ./...` 零警告
- [ ] `go test ./...` 全绿；新增/修改逻辑均有对应测试
- [ ] 新增模块 ≥10 个带断言的单元测试（表驱动优先）
- [ ] 并发场景有并发测试用例
- [ ] 核心接口压测数据已记录（工具 / 并发数 / P50 / P99 / 错误率）

## B. 架构合规

- [ ] 分层符合规范（API 只做校验鉴权，业务在 RPC / biz-data-service 依赖向下）
- [ ] 公共逻辑已下沉 common/pkg，无复制粘贴
- [ ] 无跨层调用、无循环依赖
- [ ] 错误码使用统一分段，无魔法数字/魔法字符串

## C. 安全红线

- [ ] 身份字段取登录态，前端传入的身份参数已移除
- [ ] 查/改/删带归属条件，越权用例已自测（普通用户访问他人资源返回 403/404）
- [ ] 无硬编码凭据（DSN/密钥/AK），全部走配置或环境变量
- [ ] 日志无密码、token、完整手机号
- [ ] 入口参数校验完整，GET 结构体已核对 form 标签
- [ ] 批量操作有上限，删除/状态变更有影响范围确认

## D. 并发与数据

- [ ] 并发五问有明确书面答案（超时 / 重试 / 降级 / 补偿 / 幂等）
- [ ] 缓存有穿透/击穿/雪崩防护，或写明不需要的理由
- [ ] 分布式锁有 token+Lua 释放与续期方案，或说明不需要的理由
- [ ] 迁移脚本版本化入库，历史脚本未被修改
- [ ] 新查询有索引依据（explain 验证），无循环内单条查询
- [ ] 状态流转有状态机/枚举约束，非法流转被集中拦截

## E. 文档与可讲解性

- [ ] 接口文档与契约同步更新（含错误码表）
- [ ] README / 部署说明可让他人一键运行
- [ ] 《变更说明》已按模板输出
- [ ] 每段关键代码（含 AI 生成）能脱稿讲清"为什么这么写、边界在哪"
- [ ] 需求规格 docs/specs/<模块名>.md 已归档

---

## 《变更说明》模板

```markdown
## 变更说明
- 模块/接口：
- 改了什么：
- 为什么改（对应哪条需求规格/缺陷）：
- AI 参与部分及讲解要点：
- 验证方式（测试用例 / 压测数据 / 自测步骤）：
- 影响范围与回滚方式：
```
