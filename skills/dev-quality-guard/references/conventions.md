# Go 微服务编码规范细则

阶段三（约束编码）的执行依据。编码前通读，编码中逐条对照。

## 1. 架构分层

- go-zero 项目：API 网关层（api）只做参数校验、鉴权与权限校验；业务逻辑全部下沉 RPC 层（rpc）；服务间通过 etcd 注册发现。
- Kratos 项目：biz（业务逻辑）/ data（数据访问）/ service（接口适配）三层，依赖方向只能向下，禁止反向引用。
- 公共能力（JWT 鉴权、限流、RBAC、统一返回结构、错误码）沉淀到 common/ 或 pkg/，两个以上服务要用就下沉，禁止在业务层复制粘贴。
- 禁止：API 层写业务逻辑、RPC 层拼 HTTP 响应、data 层反向调用 biz。

## 2. 命名规范

- 包名全小写短词；文件名小写下划线；导出标识符 PascalCase，局部变量 camelCase。
- 布尔变量/函数用 is / has / can 前缀； Getter 命名可省 Get 前缀（Go 惯例）。
- 表名小写、字段 snake_case、禁用数据库保留字；同一项目内单复数风格统一。
- 常量枚举集中定义（如订单状态、角色类型），禁止散落魔法数字。

## 3. 统一返回与错误码

- HTTP 统一信封：`{"code": 0, "message": "ok", "data": {}}`。
- 错误码分段：0/20000 成功；40001 参数错误；40002 业务校验失败；50001 数据库错误；50002 缓存/中间件错误。新增错误码先查表再追加，禁止随手编。
- 错误向上传递必须包装上下文：`fmt.Errorf("查询订单失败: %w", err)`；禁止吞错误、禁止空 catch。
- 业务错误使用预定义 error 变量 + errors.Is 判断，禁止魔法字符串比对。

## 4. 安全红线（逐条硬性执行）

1. 身份字段（user_id 等）一律取自登录态（JWT Claims），禁止信任前端传参。
2. 越权防护：查/改/删必须带归属条件（如 `WHERE id = ? AND user_id = ?` 双条件），越权用例纳入自测。
3. 中间件链固定「先鉴权、后授权」；管理接口禁止用路径参数传递身份；管理员权限禁止被修改。
4. 密码 bcrypt 哈希存储；手机号等敏感唯一字段按团队规约哈希或脱敏展示。
5. 凭据（DSN、密钥、AK/SK）由配置文件或环境变量注入，禁止写入代码与仓库；配置与代码分离。
6. 日志禁止输出密码、token、完整手机号。
7. 参数校验在入口层完成：GET 结构体核对 form 标签，POST 核对 json 标签，两者都要校验。
8. 删除/状态变更类操作必须确认影响范围；批量操作必须有上限与分页。

## 5. 缓存与并发

- 缓存三重防护：防穿透（空值占位，短 TTL）、防击穿（回填锁/singleflight 收敛）、防雪崩（TTL + 随机抖动）；热点数据支持预热，变更后主动失效。
- **并发五问**——每个涉及外部状态的接口必须能书面回答：
  1. 下游超时怎么办？
  2. 失败是否重试？重试几次、间隔多少？
  3. 降级方案是什么？
  4. 是否需要补偿/最终一致（本地消息、延迟队列、TCC）？
  5. 如何保证幂等（唯一键、SETNX、CAS、状态机）？
- 分布式锁：token + Lua 原子释放 + 看门狗续期；若不用锁，给出明确理由。
- 事务边界最小化；跨表一致性用乐观锁/本地消息/补偿，禁止长事务。
- 计数、限流、扣减等原子操作用 Redis + Lua，禁止先 GET 后 SET。

## 6. 数据库规约

- 新表必须有主键、created_at / updated_at；迁移脚本版本化入库，禁止修改历史脚本。
- 查询条件字段必须有索引依据（explain 验证过）；禁止循环内单条查询，改批量插入/批量查询。
- 金额用分（bigint）存储；状态字段用 tinyint + 常量 + 状态机约束，非法流转集中拦截。
- 大表查询必须分页；导出类需求必须异步。

## 7. 测试规约

- 单元测试表驱动（table-driven）、必须带断言；核心业务路径全覆盖。
- 并发场景必须有并发测试用例（例：并发抢单只有一个成功）。
- 压测：核心接口输出 P50/P99 报告，记录工具、并发数、时长、错误率；压测发现的问题转优化项追踪。
- `go build` / `go vet` / `go test` 全绿是提交底线，不绿不提。
