# dev-quality-guard 使用说明

> 项目开发质量约束技能 —— 保证学生代码产出「架构合规、可讲解、可测试、可部署」

## 一、这是什么

`dev-quality-guard` 是面向实训 Go 微服务项目（go-zero / Kratos 技术栈）的 CodeBuddy 技能。它把项目管理要求的研发流程固化成 AI 必须遵守的硬性工作流：

- **拦截"直接让 AI 生成代码再粘贴进项目"**：未完成需求梳理与规格化，禁止生成业务代码；
- **拦截"贴了 AI 代码却讲不清"**：AI 生成代码必须逐段讲解原理与边界，讲不清视为未完成；
- **统一质量底线**：架构分层、命名、错误码、安全红线、并发五问、测试与压测要求全部清单化。

## 二、适用范围

| 场景 | 是否触发 |
|---|---|
| 新建项目 / 新增模块 / 新增接口 | ✅ 必须使用 |
| 修复缺陷、重构、性能优化 | ✅ 必须使用 |
| 只读代码分析、答疑、写文档 | 可不使用 |

**触发方式**：安装后描述开发类任务时自动触发；也可显式调用——在对话框输入：

```
/dev-quality-guard 开发一个优惠券模块
```

## 三、安装与分发

### 学生安装

1. 拿到 `dev-quality-guard.zip`，解压；
2. 将解压出的 `dev-quality-guard` 文件夹放入：
   - 个人使用：`C:\Users\<用户名>\.codebuddy\skills\`（用户级，所有项目生效）
   - 团队共享：项目根目录 `.codebuddy/skills/`（项目级，随仓库分发）
3. 重启 CodeBuddy（或新开会话）生效。

### 教师分发

- 直接把 zip 发给学生按上述步骤安装；
- 或放入班级公共项目模板仓库的 `.codebuddy/skills/`，随项目初始化自动带出。

## 四、核心工作流（四阶段）

技能触发后，AI 会强制按以下顺序推进，禁止跳过：

```
阶段一 需求梳理 ──→ 阶段二 规格化输出 ──→ 阶段三 约束编码 ──→ 阶段四 质量自检
（头脑风暴澄清，   （接口契约/表结构/     （对照规范细则编码，  （DoD 清单全过 + 
 产出需求规格）      依赖与降级/验收标准）   AI 代码过三道关）     输出《变更说明》）
```

| 阶段 | 硬性产出物 | 归档位置 |
|---|---|---|
| 需求梳理 | 需求规格（目标、边界、非目标） | `docs/specs/<模块名>.md` |
| 规格化输出 | 接口契约（含错误码表）、表结构与索引依据、依赖与降级方案、验收标准 | 同上，随规格归档 |
| 约束编码 | 通过 `go build / vet / test` 的代码 + 对应单测 | 代码仓库 |
| 质量自检 | 自检清单全过 + 《变更说明》 | 提交说明 / 答辩材料 |

### AI 生成代码三道关

1. **需求先行**——没有规格，AI 不允许生成业务代码；
2. **可讲解性**——每段 AI 代码必须能回答"为什么这样写、边界在哪"，讲不清即重写；
3. **入仓评审**——提交前自查边界条件、并发安全、命名规范。

### 并发五问（每个涉及外部状态的接口必须书面回答）

① 超时怎么办 ② 是否重试/几次 ③ 降级方案 ④ 是否需要补偿/最终一致 ⑤ 如何幂等

## 五、文件结构

```
dev-quality-guard/
├── SKILL.md                  # 技能主指令：四阶段工作流、AI 三道关、DoD、红线清单
├── README.md                 # 本说明文档
└── references/
    ├── conventions.md        # 编码规范细则：分层 / 命名 / 错误码 / 安全红线 / 缓存并发 / 数据库 / 测试
    └── checklist.md          # 提交前自检清单（A-E 五组 30+ 项）+《变更说明》模板
```

## 六、教师管理用法

1. **答辩检查**：要求学生答辩时出示《变更说明》，重点核对"AI 参与部分及讲解要点"——AI 代码讲不清直接扣分；
2. **日check 周检**：自检清单（checklist.md）可直接作为周检查项引用，核对单测数量与压测记录；
3. **过程留痕**：`docs/specs/` 下的需求规格与《变更说明》纳入 Git 仓库，日check 抽查时可追溯；
4. **评分挂钩**：红线行为（身份字段取前端参数、硬编码凭据、吞错误等）触犯即打回，与周总分联动。

## 七、常见问题

**Q1：安装后没有自动触发？**
开发任务描述中包含"开发 / 实现 / 新增 / 修复 / 重构"等关键词通常会自动触发；也可显式输入 `/dev-quality-guard <任务描述>`。

**Q2：小改动也要走四阶段吗？**
修 typo、改注释类微改动可直接进行；涉及接口、数据、业务逻辑的改动一律走全流程。

**Q3：与研究院推行的头脑风暴 Skill 是什么关系？**
本技能是其落地执行层：头脑风暴等 Skill 负责"梳理需求"，本技能承接其产出并约束"编码到交付"的全过程，两者配合使用。

**Q4：能改规范吗？**
可以。直接编辑 `references/conventions.md` 与 `references/checklist.md`，改完重新分发即可；SKILL.md 的四阶段流程与红线不建议学生自行修改。
