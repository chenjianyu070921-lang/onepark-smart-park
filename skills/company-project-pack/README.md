# company-project-pack 使用说明

> 公司项目背景包装器 —— 给学生的项目配上"大厂级"的公司、架构与数据外衣，每个数字都能当场验算

## 一、这是什么

`company-project-pack` 是面向实训学生求职准备的 CodeBuddy 技能。指定一个项目类型（外卖、打车、生鲜电商、快递物流、通用电商等），它会：

1. **对标市面大型同类公司**，产出公司基本信息、研发组织架构（Mermaid 图）、学生在项目中的岗位定位；
2. **规划学生负责的模块**（3-5 个，强制包含高并发复杂功能，为亮点功能做候选）；
3. **产出支撑真实性的核心数据**：DAU、日常 QPS、峰值 QPS、核心链路 TPS、存储量级——每个数字都附推算公式，被追问"怎么来的"时能当场算；
4. **产出项目架构与技术选型**（Go：go-zero / kratos / 自研，含选择理由）、服务器配置、核心业务流程；
5. **产出项目功能结构图**（Mermaid 功能树，标注"我负责"与"高并发热点"），供学生挑选亮点功能；
6. **对选定亮点功能深挖**：需求讲解 → 难点（高并发/高可用/可靠性三维度）→ 解决方案 → 优化方案 → 测试与达标方案 → 面试追问预测（12-18 个，层层深挖）。

## 二、适用范围

| 场景 | 是否使用 |
|---|---|
| 求职前为项目构建完整公司背景与数据口径 | ✅ 核心场景 |
| 简历项目描述的量级校准（DAU/QPS/机器数） | ✅ 可用 |
| 模拟面试出题（围绕公司/架构/数据提问） | ✅ 可用 |
| 日常写代码、修 bug | ❌ 请用 dev-quality-guard |
| 已有真实代码的模块要出亮点话术 | ❌ 优先用 interview-highlight |

**触发方式**（推荐显式调用，指定类型与档位）：

```
/company-project-pack 生鲜电商，独角兽档位
/company-project-pack 网约车，对标花小猪，中厂
```

## 三、安装与分发

1. 拿到 `company-project-pack.zip`，解压；
2. 将 `company-project-pack` 文件夹放入：
   - 个人使用：`C:\Users\<用户名>\.codebuddy\skills\`
   - 团队共享：项目根目录 `.codebuddy/skills/`
3. 重启 CodeBuddy（或新开会话）生效。

## 四、产出物说明

运行后在项目内生成两个文档：

**1. `docs/company-pack/company.md` —— 公司项目背景包（八项）**

| 项 | 内容 |
|---|---|
| 公司基本信息 | 名称（对标真实公司或化名）、规模、业务线、行业地位 |
| 研发组织架构 | Mermaid 图：事业群→事业部→技术部→项目组，人员配比 |
| 我的定位 | 岗位、所在组、汇报关系、协作方 |
| 负责模块 | 3-5 个，含 1-2 个高并发复杂功能，标注上下游依赖 |
| 核心业务数据 | DAU / 日常 QPS / 峰值 QPS / TPS / 日订单量 / 存储量级，全部附推算公式 |
| 服务器与基础设施 | 机器规格与数量、中间件集群规格、监控日志体系 |
| 架构与技术选型 | Go 框架选型理由、存储与中间件、服务拆分与部署 |
| 核心业务与流程 | 主链路分步描述（用户视角 + 系统视角） |

**2. `docs/company-pack/function-map.md` —— 项目功能结构图**

- Mermaid 功能树（平台 → 端 → 功能域 → 功能点）；
- ★ 标注"我负责"与"高并发热点"；
- 附 3-5 个亮点功能候选及"可讲性"评估。

**3. 亮点功能深挖 + 追问预测**（选定亮点后继续生成）

- 六段讲解：需求 → 难点（高并发/高可用/可靠性）→ 方案 → 优化 → 测试达标 → 电梯句；
- 追问预测 12-18 个，**必考"数据怎么来的"**——用推算公式现场回答。

## 五、数据可信度规则（本技能的核心价值）

- **记公式，不记结果**：日请求 = DAU × 人均请求数 → 平均 QPS = 日请求 ÷ 86400 → 峰值 = 平均 × 峰值系数（3-5）→ 下单 TPS ≈ 峰值 × 15%；被追问时现场推算反而加分；
- **量级与档位匹配**：DAU 50 万的公司不会出现 5000 台机器；架构、选型、机器数必须与数据档位互相自洽；
- **口径全文一致**：公司名、DAU、QPS、框架在简历、讲解稿、追问答案里完全相同；
- **表述口径建议**：面试说"一家做 XX 业务的公司 / 对标美团"，比直接声称真实大厂在职更稳，避免背调风险。

## 六、与其他两个技能的配合（就业三件套）

| 阶段 | 技能 | 作用 |
|---|---|---|
| 1. 定背景 | company-project-pack（本技能） | 公司是谁、数据多少、架构怎么搭、负责什么 |
| 2. 写代码 | dev-quality-guard | 按四阶段流程把模块真实做出来，保证可讲解 |
| 3. 备面试 | interview-highlight | 基于真实代码生成亮点话术 + 追问预测 |

推荐顺序：先用本技能定背景与数据口径 → 开发时让代码规模与口径匹配 → 求职前用 interview-highlight 出话术。

## 七、教师管理用法

1. **就业材料审核**：检查学生背景包的数字能否用推算公式闭环（DAU→QPS→机器数），推不圆的直接打回；
2. **模拟面试出题**：围绕"数据怎么来的、为什么这个架构、量级涨 10 倍怎么办"提问，检验是否真懂；
3. **简历校准**：简历上的 DAU/QPS 必须与背景包一致，避免多家机构包装口径打架；
4. **统一口径**：同班学生避免用完全相同的公司名与数据组合，分配不同档位与业务线。

## 八、常见问题

**Q1：可以指定真实公司吗？**
对标真实公司提取业务量级没问题，但建议面试表述用"对标/类似"口径，公司名用化名，避免背调环节穿帮。

**Q2：数据会不会太大露馅？**
技能内置档位匹配约束：公司档位、DAU、QPS、机器数、框架复杂度必须互相匹配；推算公式就是用来现场自证合理性的。

**Q3：和我自己的实训项目对不上怎么办？**
背景包支持沿用实训项目名（叮咚买菜、花小猪、顺丰等），档位选"成长期中厂/独角兽"即可与实训代码规模匹配。

**Q4：怎么调整行业基准或公式？**
编辑 `references/data-benchmarks.md`（量级基准表、推算公式、组织架构模板、服务器规格），按目标行业与最新市场情况更新。
